# 生产部署

当前生产域名为 `https://speakquant.com`，服务器 SSH 别名为 `speakquant-sg`。前端仓库位于 `/opt/speak-quant-ui`，后端仓库位于 `/opt/speak-quant-api`。

请求链路：浏览器 → Nginx → `/` 转发至 Nuxt `127.0.0.1:6002`；`/api/` 转发至 FastAPI `127.0.0.1:6001`。两个服务分别由 systemd 管理，Node 与 API 端口不向公网开放。

## 首次部署前提

- Linux 上已安装 Git、Nginx，能拉取 `bingyi20/speak-quant-ui` 仓库。当前服务器通过公开 HTTPS 地址只读拉取；私有仓库需配置该仓库的只读 Deploy Key。
- 域名、HTTPS、后端和数据库已就绪；`https://speakquant.com/api/health` 返回成功。
- 使用符合 `package.json` 的 Node `>=22.13.0 <23` 与 pnpm `10.32.1`。当前生产 Node 为 `22.23.3`，隔离安装于 `/opt/node22`，保留机器原有 Node 24；更换版本时同时核对项目依赖与 service 路径。
- 创建专用系统用户 `speakquant-ui`，不授予 Docker 组权限。该用户须能读取仓库和构建产物、执行 `/opt/node22/bin/node`，无需写入产品代码。

仓库代码与部署配置均遵循：本地修改、验证、推送 Git → 服务器拉取 → 安装配置并发布。生产 `.env` 可直接调整，不提交密钥或真实配置。

## 环境配置与构建

首次将仓库克隆至 `/opt/speak-quant-ui`，从 [生产环境示例](../deploy/.env.production.example) 创建 `.env`；已有配置不要覆盖。至少核对：

```dotenv
NUXT_PUBLIC_API_ENABLED=true
NUXT_PUBLIC_API_BASE=/api
NUXT_API_BASE=http://127.0.0.1:6001/api
NUXT_PUBLIC_SITE_URL=https://speakquant.com
```

`NUXT_PUBLIC_API_BASE` 用于浏览器，`/api` 自动使用当前网站域名；`NUXT_API_BASE` 用于服务端读取公开接口，必须使用绝对地址。前端不增加 API 代理或 BFF。公开公司、联系方式及功能开关按示例核对，`NUXT_PUBLIC_*` 会进入浏览器，不能存放秘密。

以 root 安装依赖和构建，设置正常读取权限；不要与同目录开发服务同时构建：

```bash
cd /opt/speak-quant-ui
umask 0022
export PATH=/opt/node22/bin:/usr/local/bin:/usr/bin:/bin
pnpm install --frozen-lockfile
NODE_OPTIONS=--max-old-space-size=2048 pnpm build
chgrp -R speakquant-ui /opt/speak-quant-ui
chmod -R g+rX /opt/speak-quant-ui
chown root:speakquant-ui .env
chmod 0640 .env
```

生产直接运行 `.output/server/index.mjs`，不使用 `pnpm dev`。Node 启动构建产物不会自动加载 `.env`，由 systemd 的 `EnvironmentFile` 注入运行环境。

## systemd 与 Nginx

安装仓库中的 [service 模板](../deploy/speakquant-ui.service)：

```bash
install -m 0644 deploy/speakquant-ui.service /etc/systemd/system/speakquant-ui.service
systemctl daemon-reload
systemctl enable --now speakquant-ui
systemctl status speakquant-ui --no-pager
curl --fail --silent --output /dev/null http://127.0.0.1:6002/
```

完整 Nginx 模板由**后端仓库**维护：`/opt/speak-quant-api/deploy/nginx-app-https.conf.example`。包含现有 ACME、HTTPS、`/api/` SSE 配置及 `/` Nuxt 转发。首次接入前备份现有站点，确认模板域名和证书路径后安装：

```bash
cp -a /etc/nginx/conf.d/speakquant-api.conf /etc/nginx/conf.d/speakquant-api.conf.before-ui
install -m 0644 /opt/speak-quant-api/deploy/nginx-app-https.conf.example /etc/nginx/conf.d/speakquant-api.conf
nginx -t && systemctl reload nginx
```

备份文件不以 `.conf` 结尾，避免被重复加载。`/api/` 的 `proxy_pass` 不追加 URI 或尾部 `/`，须保留原始 `/api` 前缀；流式接口须保留关闭缓冲和长读取超时配置。

## 更新与回滚

更新前确认服务器工作区干净，备份 `.output`、`.env` 并记录旧 commit。备份目录权限设为 `0700`，不要放入仓库或网站静态目录。然后执行：

```bash
cd /opt/speak-quant-ui
git status --short
# 确认工作区干净、备份已完成后停止前端，再更新构建。
systemctl stop speakquant-ui
git pull --ff-only
export PATH=/opt/node22/bin:/usr/local/bin:/usr/bin:/bin
umask 0022
pnpm install --frozen-lockfile
NODE_OPTIONS=--max-old-space-size=2048 pnpm build
chgrp -R speakquant-ui .output
chmod -R g+rX .output
systemctl restart speakquant-ui
curl --fail --silent --output /dev/null https://speakquant.com/
curl --fail --silent https://speakquant.com/api/health
```

当前为单机原地构建，停止前端到构建验收完成期间不可用，安排维护窗口；不要在运行中的 `.output` 上构建。构建失败时先恢复同一备份的 `.output` 与匹配的 `.env`，检查权限后启动，不启动不完整的构建产物。代码回滚通过本地 `git revert`、推送、服务器拉取及重新构建完成，不直接修改生产仓库。service 有变化时重新安装并 `daemon-reload`；Nginx 配置有变化时从后端仓库拉取安装，`nginx -t` 成功再 reload。

## 验收与排查

- 检查 `/`、`/zh-CN`、`/pricing`、`/privacy`、`/terms`、`/contact`、`/login` 及静态资源；首页 HTML 应包含 SSR 内容。
- 浏览器网络请求应指向 `https://speakquant.com/api/...`，不得出现 localhost。邮箱登录、刷新恢复、退出和 SSE 需使用真实后端验证；Google 登录还要求 OAuth 授权来源包含正式域名。
- `journalctl -u speakquant-ui -n 100 --no-pager` 查看启动异常；`systemctl status speakquant-ui` 与 `ss -lntp` 核对 `127.0.0.1:6002`。
- 首页 502：先访问本机 6002，检查 Node 路径、服务用户读取权限、`.output/server/index.mjs` 与 EnvironmentFile。
- 页面正常但 API 失败：检查生产环境变量、浏览器实际请求及 Nginx `/api/` 路由；后端日志使用 `journalctl -u speakquant-api`。
- 修改 `.env` 后需重启前端；出现旧资源、资源 404 或 hydration 异常时，核对 HTML 与静态文件来自同一次构建，再排查缓存。
- SSE 延迟集中输出：检查 `/api/` 的缓冲、压缩、超时和中间代理；登录无法保持时检查 HTTPS、Refresh Cookie 及后端配置。

本次生产验收（2026-10-09）：构建、systemd、首页和中英文/价格/政策/登录路由、静态资源及同域 API 检查通过；浏览器请求未指向 localhost。没有代用户执行完整账号登录、Agent 或回测。

已知现象：游客直接打开或刷新登录页时，Google 入口首次显示不可用，点击重试后恢复。代码中身份恢复返回 401 会触发 `http.cancelAll()`，可能取消同时发出的公开 Google 配置请求；需由前端进一步验证并修复初始化生命周期。本次仅部署和调整环境/进程/代理配置，保留前端业务实现。

后端数据库、证书续期、备份恢复和迁移参考后端仓库 `docs/后端部署与运维指南.md`。前端部署不代表支付业务已经接入。
