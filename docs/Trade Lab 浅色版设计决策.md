## 1. 文档用途与决策状态

本文维护当前有效的视觉与交互规范，承接已确认的原型方向和正式前端修订。更新直接落在对应主题章节，不按每次修改追加流水账；业务流程由专项技术方案维护，验证结果进入联调记录。

- **已确认**：用户明确选择的方向、明确要求的行为与尺寸，应延续到后续版本。
- **原型参考**：当前页面实际使用的字体、辅助颜色、间距和动效等；可作为起点，但不等于每个数值都已逐项确认。
- **待打磨**：正式产品仍需设计、实现或验证的细节，不能把演示行为直接当作生产规格。

业务规则继续参考 [PRD](./Trade%20Lab%20MVP%20PRD.md)、[产品决策](./产品决策.md) 和 [MVP 交互方案](./Trade%20Lab%20MVP%20交互方案.md)。本文补充本轮浅色视觉及交互修订，不另建一套完整业务流程。原型与业务文档不一致时，应识别为待对齐项；不能因原型省略了功能，就推断该需求已经取消。

## 2. 核心设计方向（已确认）

### 2.1 产品气质

安静、清晰、理性、睿智，同时保留温度、金融研究的仪式感和发现问题时的兴奋感。

- 参考 Claude 的信息组织与克制程度：像与一位理性、睿智的人一起工作。
- 参考 Creem 的表达与反馈：可以形象、有个性、灵动，但注意力主次必须明确。
- 金融感通过精确的数字、图表、时间、证据与操作反馈建立。
- 兴奋感集中在策略形成、回测完成、关键事件出现的时刻。

参考网站：[Claude](https://claude.ai/)、[Creem](https://www.creem.io/)。参考的是体验取向，不复制品牌资产或整套样式。

### 2.2 表达纪律

> **非必要不解释，非必要不强调。克制不等于死板，灵动留在交互里。**

1. 同一个信息尽量只在一个适合的位置重点呈现。
2. 对话提供结论，Replay 提供指标、行情和证据。
3. 不用大量加粗、彩色数字、卡片、标签同时争夺注意力。
4. 不为表达“专业、可信、睿智”而反复增加说明性文案。
5. 删除无助于理解或操作的内容，而不是缩小字体、降低对比度来隐藏它。
6. 保留有意义的悬停、按下、展开、选中和定位反馈。

已删除的典型冗余包括：“研究伙伴”身份标签、“基于本次历史回测 · 可追溯的研究证据”、重复标语、对话内重复的收益大数字与装饰性小图。

## 3. 浅色主题与颜色

### 3.1 品牌主色（已确认）

**赭金 `#986B2C`**。

用户确认理由：有金融感，同时有一定区分度；温暖，符合产品气质。

使用方式：

- 少量用于品牌符号、发送按钮和主要操作。
- 保持纯色、低饱和、哑光的感觉。
- 不扩展为大面积金色背景，不添加金属渐变或发光效果。
- 正文和常规边框以中性色为主。
- 品牌色与涨跌、盈亏颜色分开承担语义；赭金不表示盈利。

**交互边框规则（已确认）**：交互保持克制、简洁、轻量。除非用户明确要求，不新增强调边框、选中描边或焦点外圈，金色、灰色均不例外；禁止把“去掉金色边框”实现为换一种颜色继续画框。按钮、链接和卡片在点击、键盘聚焦及 Esc 恢复焦点后，不新增 outline、ring 或模拟外圈的阴影，也不加深、加粗原有边框。共享样式默认不为按钮和链接绘制焦点轮廓，控件只使用轻微文字/图标颜色反馈；卡片只加深打开箭头，保留普通边框。保留实际焦点、Tab/Enter/Space 和分层 Esc 行为，不能用 blur 绕开样式问题。输入框自身的编辑焦点反馈、已有明确业务语义的选中态分别遵循对应组件规范。

## 4. 字体与排版

### 4.1 设计方向

- 日常对话与操作文字清晰、自然，适合长时间阅读。
- 首页标题带少量书卷感，形成温暖、沉静的气质。
- 指标数字清晰、有分量，但不在对话与 Replay 两处重复突出。
- 日期、时间和需要比较的数字保持稳定对齐。

### 4.2 当前原型字体（参考，尚未逐项定稿）

| 用途 | 字体栈 |
| --- | --- |
| 正文 / 通用 UI | `"Avenir Next", "PingFang SC", "Microsoft YaHei", sans-serif` |
| 首页标题 | `"Songti SC", "STSong", Georgia, serif` |
| 回测指标大数字 | `Georgia, "Times New Roman", serif` |
| 时间 / 部分数字元信息 | `"SFMono-Regular", Consolas, monospace` |

字体依赖系统可用字体回退，当前没有把上述字体打包为 Web Font。不同操作系统的结果不完全相同；正式产品需确认中英文字体、授权、加载与回退方案。

### 4.3 当前字号参考

- Agent 正文：`16px`，初始回复行高 `1.9`。
- 用户消息：当前 `14px`；正式产品需与 Agent 正文共同复核。
- 常用导航与操作标题：主要为 `14px`。
- 公共首页标题：桌面 `clamp(36px, 4.2vw, 61px)`，行高 `1.22`；小屏 `clamp(32px, 7.8vw, 48px)`，行高 `1.3`。
- 回测指标：通常 `29px`，小屏 `27px`。
- 次级信息主要为 `12–13px`，部分日期、图表和脚注仍小于 `12px`，需后续复核。

克制应通过精简与排版实现，不能用过小、过浅的文字代替信息取舍。

## 5. 全局布局与导航

### 5.1 页面结构

沿用左侧研究历史、中央对话、右侧按需展开资产的框架。首页聚焦输入研究想法，不增加行情仪表盘等无关入口。

登录页 Google 入口使用官方 GIS 标准按钮，沿用 50px 高和现有全宽布局，按钮外观由 Google SDK 管理。加载、不可用和 challenge 过期时在原按钮位置呈现轻量状态及重试，邮箱入口始终可见；错误向读屏器公告。登录中锁定重复操作，首次第三方邮箱补验复用现有六位验证码步骤。验证码输入框聚焦时保留原细边框与光标，不显示外圈或阴影、不加深边框；错误态继续使用原错误边框。邮箱验证码登录流程保持不变。条款／隐私告知独立放在登录页底部，入口与验证码步骤共用；最大宽 400px、12px 次要文字、1.6 行高、居中自然换行，链接保留下划线及新标签页打开。表单区居中，告知区与表单至少相隔 48px、距页面底部至少 24px，并适配底部安全区；短屏按正常文档流滚动，不固定覆盖表单。

正式前端桌面侧栏统一使用 `--sidebar-width: 260px`，左、右、下内边距均为 `8px`。`/` 是公共落地页，`/new-task` 是工作台新研究页，不把两个入口的外围布局混为一体。

落地页保留暖白画布、系统衬线主标题与赭金标点。首屏英文主标题采用[落地页改造 PRD](Trade%20Lab%20落地页改造%20PRD.md)定稿，中文主标题保持“3 分钟，验证你的交易想法。”。副标题采用用户最新中英文定稿：“Turn market ideas into evidence — explore, test, and refine strategies with AI.”／“让交易想法变成证据，与 AI 一起探索、验证并迭代策略。”，随可用宽度自然换行。真实输入与四个示例共享工作台控件，最大宽度 736px。下方研究绘图区放宽至最大 960px，以“从想法到证据，再从证据出发。”引入 BUILD → TEST → LEARN → BUILD。初始想法位于环外，以一颗小星芒和“一个想法”从上方进入 BUILD；星芒首次进入视野时轻亮一次后静止，减少动态效果时不播放。三个节点各自包含线性图示、标题和一句精简说明，不使用卡片边框。图示用同一套交易语汇表达三步：BUILD 将包含行情想法的气泡转为条件分支与 B/S 买卖动作；TEST 在简化 K 线上使用 B/S 标签、细引线及成交圆点，保留轻量回放进度；LEARN 对比两种交易结果，以放大镜强调差异并引出问号气泡。B/S 使用统一浅金底和品牌色字母，不沿用真实交易界面的红绿配色；图中不放收益数字或真实策略结论。桌面三列，标注“下一个假设”的回路线从 LEARN 全部图文下方回到 BUILD 下方；手机采用左图右文的三行，回路线沿左侧直接接入 BUILD，不回到初始想法。线路使用 `--color-diagram-connector`，星芒光晕使用 `--color-idea-glow`，由浅色／深色主题统一定义。金色仅点出阶段、方向和重点，不持续播放闭环动画。移除额外的结果总结句，保留次级业务边界。图示只说明研究方法，不展示模拟收益或交互界面。公开页样式集中于 `public.css`。

公共顶栏仅提供价格、语言与登录／工作台入口；手机也将账号按钮常驻在右侧，与价格及语言同排，不再提供折叠菜单。桌面与手机顶栏统一为 60px 并固定在顶部，正文预留同高空间；背景采用主题变量 `--color-bg-public-header`（画布色 82% 不透明度）和 12px 背景模糊，不加阴影或分隔边框。语言触发区域保持至少 44px，悬停、展开与键盘聚焦不变底色，以文字略微加深和箭头转向提示状态，按下轻微降低透明度；菜单选项沿用共享样式。公共语言菜单不锁住页面滚动，开合前后保留滚动条；桌面价格、语言与账号入口分别固定为 64px、52px、112px，避免语言长度变化导致横向位移。760px 以下保留完整品牌字标，缩至 16px，Logo 为 24×24px；顶栏两侧留白 16px，导航间距 6px，价格、语言与账号入口分别为 56px、48px、88px。360px 以下两侧留白收至 12px，品牌字标 15px、Logo 22×22px，导航间距 4px，三个入口宽度依次为 44px、40px、80px；导航文字收至 12px，手机各入口触控高度至少 44px。Logo 字标悬停保持原正文色，键盘聚焦用轻微透明度反馈。研究流程仅保留首页正文。页脚提供价格、隐私、条款与联系，不显示历史表现提示；开源入口放入服务条款，取消与退款合入价格页。隐私政策与服务条款正文宽 736px（不含外围留白），与价格问答共用 `--conversation-width`，标题、更新日期、正文自然排列，已填入运营者与邮箱时不显示草案，仅在信息缺失时保留轻量草案提示；联系信息由共享配置提供，不生成无效邮箱链接；隐私与条款正文只保留邮件链接，联系页入口统一留在页脚。政策分节可包含多段正文，段间留白 12px；用户声明及禁止行为使用轻量项目列表，条目间距 8px，沿用正文颜色与行高。价格页完整复用工作台订阅组件，标题、套餐／积分加购页签、卡片按钮位置和金额表单均一致，使用同一套真实套餐、报价与同页付款流程；套餐页不展示账户信息／刷新区，访客购买先登录，加购仅对有效付费订阅开放。套餐下方以五个短问答说明套餐差异、积分消耗、额度用完、续费取消与退款，上方增加居中的“常见问题 / Frequently asked questions”二级标题，问题使用三级标题。问答保留现有展开式正文，正文左对齐；内容最大宽 736px 并居中，手机两侧留白 20px。积分只解释消耗原则，不列模拟数值或逐项计价表；共享计费说明标明 USD 币种。

### 5.2 侧栏收起按钮（已确认）

- 放在左侧导航栏内部，Logo 右侧，与 Logo 同一水平线。
- 桌面不再在聊天 Header 左侧重复放收起按钮。
- 导航收起后，在侧栏原位置保留展开入口。
- 小屏因侧栏使用抽屉，保留 Header 的打开导航入口。

### 5.3 聊天内容宽度（已确认）

- 正文内容宽度以 **736px** 为基准，空间充足时保持该宽度并居中。
- 底部输入框与正文内容列对齐。
- 输入框悬浮在完整消息区域的底部，消息滚动条延伸到页面最底部，不再拆成上下两个独立区域。
- 消息底部留白按输入浮层的实际高度加 `24px` 计算，快捷问答展开或收起时同步更新，保证最后一条消息可完整滚出遮挡区。
- 输入浮层变高或变矮时只调整留白，不自动滚动背后的消息，允许暂时遮挡内容，避免打断输入；用户可手动滚动查看。
- 输入浮层上沿使用 `32px` 的画布色渐变，越往上越透明；渐变允许滚轮穿透，输入框保持可操作，回到最新消息按钮位于浮层上方，采用 `36px` 圆形按钮和 `20px` 向下箭头，不显示文字，保留无障碍名称。
- 736px 指内容区域，不包含外围留白。
- Markdown 表格统一占满正文内容宽度，不按内容收缩；超过可用宽度时仅表格区域横向滚动。
- 分屏或小屏空间不足时自适应缩小，不产生横向溢出。
- 当前桌面两侧最小留白 `30px`，小屏 `16px`，正文与底部输入使用相同留白和滚动条占位；分屏拖动、侧栏切换后两侧仍保持对齐。
- 落地页与新研究页输入区也采用同一 736px 上限，通过 `--home-width: var(--conversation-width)` 共享规格；窄屏随可用空间收缩。

### 5.4 聊天 Header（已确认方向，尺寸为本轮采用值）

- 压低高度，保留必要上下文和操作，减少空间占用。
- 工作台页头统一固定为 **48px**，新建页与对话页共用；左侧导航的 Logo 与展开/收起按钮同步居中，路由切换不改变导航条目的纵向位置。
- 背景与聊天画布相同，为 `#FAF9F6`。
- 移除硬分隔线；下沿使用同底色向透明渐隐，越向下越透明。
- 当前渐隐区域高 `22px`，不阻挡鼠标或触摸操作。
- Replay 展开后覆盖右侧 Header 区域，不在面板顶部继续预留全局 Header 的高度。

### 5.7 全局样式与滚动条

颜色和排版使用全局语义变量，字体集中在 `tokens.css`，不在各页面分散定义。深色设计确认前保持 `NUXT_PUBLIC_ENABLE_DARK_THEME=false`；系统文案同步中英文，研究标题等用户内容不自动翻译。

回测相关系统文案统一使用“回测 / Backtest”，记录列表为“回测记录 / Backtests”；页面标题、卡片、按钮、空态、错误提示与无障碍标签保持一致。沿用[产品术语](产品决策.md#产品术语)，不将内部 Replay 命名显示为业务名称。用户及服务端提供的研究名称、正文保持原样。

滚动条采用透明轨道、淡灰细滑块，颜色由 `themes/light.css` 与 `themes/dark.css` 的语义变量统一控制。全局客户端插件捕获各区域的实际滚动，滚动时显示该区域滑块，最后一次滚动约 800ms 后用 160ms ease-out 淡出，再次滚动立即取消淡出并显示；聊天主区、侧栏、右侧卡片、弹层和横向代码区各自计时。隐藏只把滑块变透明，不切换宽高、overflow 或占位，保持布局与正文位置稳定。普通和悬停滑块同步淡出，减少动态效果偏好下直接隐藏；仅显示期间悬停略加深，保留原生滚动、拖动及键盘操作；原本明确隐藏滚动条的控件维持原规则。

### 5.9 加载反馈

首载与局部刷新使用同一组共享控件：`LoadingSpinner` 为中性灰细圆环，默认 24px、紧凑场景 16px，等待持续 200ms 后才显示，快速完成不显示圆环；等待期间保留同尺寸占位，完成立即隐藏，不人为延迟真实内容。同一次聊天回复等待在快照切换前后共用起始时间，不重新计时。轨道与旋转弧颜色由两份主题文件管理；`LoadingState` 负责区域居中与读屏提示，默认不增加可见 Loading 文案；`LoadingSkeleton` 只用于结构和尺寸已知的缺失字段或按钮。减少动态效果时关闭旋转及骨架呼吸。已有工具运行图标保留其业务含义，不一律替换成圆环。

首次历史、策略和资产加载在所属内容视口居中；聊天历史加载不进入 Assistant 回复区。生成首字前仍在回复首行使用紧凑圆环，保持既有首行和工具占位，不推动完成后的正文。已有内容刷新、翻页及查看周期切换保留可读内容，只在局部表示等待，失败提供对应重试，不能以骨架覆盖真实错误或空状态。

价格页保留公开套餐正文 SSR；认证／权益未确定时，页签区域使用与真实页签同尺寸的圆角骨架并保留固定高度，购买按钮使用等高骨架，不提前展示错误的订阅按钮状态。确定资格后页签、按钮在原位出现；无订阅没有伪页签，保留轨道占位，避免卡片及 FAQ 被后插页签推移。回测详情首载居中加载，行情及图表库初始化在固定图表区域内居中反馈，原图可读时不整图遮罩；指标缺失用既有占位，交易目录未就绪不能显示成无成交。

### 6.1 Agent 回复（已确认）

**回复前不显示 Logo，也不显示 “SpeakQuant” 名称，直接渲染内容。**

Agent 与策略 Design 共用 `MarkdownContent` 和 `main.css` 中的 `markdown-prose` 样式。Markdown 正文字号桌面为 `16px`、小屏（≤700px）为 `15px`，正文行高为 `1.625`，相邻普通内容块的段间距为 `0.75em`，随字号缩放；字号为 `16px` 时对应行高 `26px`、段间距 `12px`。标题、代码块行高及列表项间距沿用各自样式。

首字状态规则：

1. 请求已发出，但尚无第一个字符：在回复容器内的第一行保留占位，持续等待 200ms 后显示轻量圆环，占位行高与正文一致，空工具区放在其下方。
2. 第一个字符开始显示：移除 Loading，由正文在同一行原位承接；空消息创建和首字切换不额外改变占位高度，避免底部跟随时跳动。
3. 后续流式输出：保留已输出内容，不同时显示 Loading，也不重新插入身份标题。
4. 历史完成的回复直接显示内容，不重演 Loading。

首字占位使用轻量 Spinner。原型演示中的 `650ms` 等待和后续定时分段输出只是模拟首字行为，**不是生产等待时长要求**。真实回复由返回内容驱动：少量文字连续出现，不做整段淡入或重复加载；已有段落、表格及代码块保持原位。用户上滚停止跟随，历史恢复不重演吐字。工具区生成期间保留单行最小高度，通过透明度切换提示，避免反复挤动内容。吐字队列、Snapshot 与滚动实现参数统一见 [Agent 对话模块技术方案 §8–9](./Agent%20对话模块技术方案.md#8-消息与卡片-ui)。

### 6.3 下一步建议（原型方向，尚未接入）

- 不插在回答正文末尾形成额外强调块。
- 放到通用输入框上方，以轻量建议呈现。
- 点击填入输入框，用户可修改；不直接提交。
- 当前原型在输入框为空、无引用且尚无后续消息时显示该建议。
- 输入框占位建议 / Tab 接受曾讨论，但本轮没有采用为正式行为，也未实现。

Agent 消息左下角显示复制图标（16px、28px 点击区）和 12px 次级色时间。最新 Agent 消息在流式与吐字队列结束后常显；操作栏与生成期空工具占位使用相同的 44px 空间，结束时只切换内容，不增加高度或推动页面。已有卡片时提前在卡片下方保留隐藏且不可交互的操作栏。历史消息悬停延迟 100ms 淡入，移出延迟 180ms、用 120ms 淡出；键盘焦点也可显示，减少动态效果模式取消过渡。隐藏工具栏保留空间，避免正文跳动。复制完整原始 Markdown，成功后仅图标短暂变为对勾，不显示 Copied / 已复制文字；失败时保留文字反馈。按浏览器本地日期显示：当天 HH:MM，非当天中文 M月D日 HH:MM，英文 Sep 9, 14:30。

聊天内资产卡片采用紧凑附件样式：最大宽度 520px，距上方内容 12px，内边距上下 12px / 左右 16px；左侧为 56×56px 文档页签，底边与卡片下沿相接并裁切，配 20px 赭金线性图标，淡色底和细边框统一使用 document 主题变量；右侧为 14px 单行标题和 12px 类型文字。长标题省略并提供完整 title 提示，不展示长摘要或指标，不设下载按钮；生成中或失败状态以简短副行文字保留。整卡点击打开详情面板，鼠标悬停时中性色细边框轻微加深，增加淡阴影并加深右侧小箭头，背景不变、不位移；边框和阴影采用 160ms 过渡，减少动态效果模式取消过渡。hover 样式仅用于支持悬停的设备；选中状态不另加金色描边。键盘聚焦及 Esc 关闭详情后恢复焦点时，保持原有普通 1px 边框，不加深、不增加 outline 或 ring，仅轻微加深右侧打开箭头。颜色和阴影统一引用主题变量。

资产列表直接复用同一个 `MessageCard.vue`，卡片宽度随列表容器收窄，保持附件页签、标题和类型的统一样式。列表平铺排列，策略卡片在前、回测卡片在后，卡片间距 10px；不显示类型分组标题、数量或分组空态。列表左右内边距 20px，仅在没有任何资产时显示统一空态。

### 6.4 输入基础行为

- 输入框使用箭头发送按钮，不增加“验证策略”等按钮文字。
- 共享研究 / 消息输入框在默认、悬停和聚焦时均使用普通细边框 `--color-border-default`，不切换金色边框；悬停或聚焦时阴影切到主题变量 `--shadow-composer-active`，以 160ms 轻微加深，减少动态效果时直接切换。浅色活跃阴影为 `0 4px 22px rgb(48 49 46 / 7%)`。
- 空输入不可发送。
- Enter 提交，Shift+Enter 换行；中文输入法组合输入期间不误提交。
- 对话输入框最小 2 行，按文字实际显示高度（包含自动折行）增高或缩小，最多显示 16 行，超出后在输入框内部滚动。共享的新研究输入保留初始 3 行；粘贴、草稿恢复和分屏宽度变化时同样自动调整。
- 落地页与新研究页使用同一套 `ResearchEntry` 展示：最大宽度 736px，与对话页底部输入框共用宽度变量，默认隐藏键盘提示，输入框初始 3 行；外围标题、导航和页面布局分别保留。快捷示例统一使用主题表面色（浅色为白底）、主文字色和 500 字重、完整不透明的赭金折线，不显示右下角箭头；保留普通细边框、12px 圆角、16px 内边距。桌面四列、760px 以下两列，卡片间距 12px、距输入框 18px。可用卡片在支持悬停的设备上仅使用极浅中性底色反馈，按下时同样反馈；键盘聚焦仅用标题的轻微品牌色反馈，边框保持不变，不新增外圈或位移。挂载前、提交中或有待处理提交时保留真实禁用态，不应用悬停反馈。点击示例填入并聚焦输入框，允许编辑，不直接运行。
- 草稿保留及访客发送后的登录恢复已接入，具体提交与恢复规则见 [Agent 对话模块技术方案 §5](./Agent%20对话模块技术方案.md#5-创建发送与草稿)。
- 用户点击发送后立即显示正常气泡，不显示发送中或成功标记；失败时提供轻量提示与重试。回复期间输入可编辑、所有发送入口禁用，本期无暂停按钮。

“回到最新”按钮在消息视口距底部超过 60px 时出现，回到 10px 以内隐藏，中间区间保持原状态。轻微上滚只暂停自动跟随，不立即显示按钮。

### 6.5 Clarification 快捷问答

Clarification 使用底部逐题卡片，展开时位于普通输入框上方，普通输入框始终可见，与正文同宽；每次只显示一道题，顶部为题目、题号 / 总数、前后导航及关闭按钮；三个图标按钮悬停仅加深图标颜色，不显示背景块，保留原有点击范围与键盘焦点提示。选项以带数字标记的整行纵向排列，每项下方均显示细分割线，包括最后一项。选择后进入下一题，最后一题确认答案或 Skip 时统一提交；自定义回答采用底部轻量输入行，编辑图标为 12px，沿用选项数字的 24px 圆角底座，文字直接在图标后输入，右侧始终放置1px 细边框、透明背景的 14px 按钮，中文“跳过”、英文“Skip”，悬停仅加深文字颜色，不带箭头且不因当前答案为空而禁用；输入框无边框和金色焦点环，自定义输入行保持透明背景，不突出于快捷选项，鼠标移入和输入聚焦均不改变背景。占位文字为“输入其他回答，按回车确认”，使用 14px 常规字重、主题变量 `--color-text-placeholder`（浅色为 80% 的 muted 文字色），弱于选项和实际输入文字；实际输入保持 16px 主文字色。Enter 确认并继续、Shift+Enter 换行，输入法组合期间不前进；输入区最高 120px。每题均可 Skip，不区分必答 / 选答，不显示第二个跳过入口；末题 Skip 提交此前已填的有效答案，全部跳过也可结束问答（待后端支持，见接口文档）。卡片采用 `16px` 圆角、表面背景及细边框，选项行最小高 `48px`；小屏顶部导航与题目分行，卡片限高 `min(48dvh, 440px)`、选项内部滚动；卡片和普通输入框间距 12px，展开时普通输入最多显示 4 行，收起后恢复 16 行，避免挤占小屏空间。

关闭卡片聚焦普通输入框，草稿始终保留，在输入框发送按钮左侧保留“问答图标 + 题数”的紧凑入口和已填答案；入口为透明背景、次级文字色，悬停仅加深颜色，完整“继续回答 · N 个问题”提示通过 title 和无障碍标签提供；关闭时卡片以 240ms 向发送按钮左侧问答入口缩小并淡出，入口自身保持静止，不闪动、缩放或淡入。离场卡片脱离布局且不可交互，输入框立即可用；快速重开中断动画，减少动态效果模式直接切换。关闭不代表已答或跳过整组。只激活最新一轮问题，已答题不再显示重复的已答题数 / 折叠答案，统一通过用户消息回看；未答旧题保留只读记录，刷新恢复已填答案。协议与逐题交互规则见 [Agent 对话模块技术方案 §8.3](./Agent%20对话模块技术方案.md#83-底部逐题快捷问答)。

## 7. Replay 面板与研究体验

资产列表与详情使用独立面板组件，各自维护布局和进出场动效。列表背景采用 `--color-bg-canvas`，与聊天内容区一致；内部附件卡片沿用 `--color-bg-surface`。大于 760px 时列表本体固定 384px 宽，连同左侧 4px、右侧 8px 间距占用 396px，从右向左进入并同步压缩聊天，关闭时向右收起。列表右、下距页面边缘 8px；顶部位于 48px 工作台页头下方，保留 4px 间距，Header 高 52px，仅保留标题，左右内边距 20px，与卡片对齐；无关闭按钮或底部分割线，没有调宽与全屏入口，通过页头资产按钮或 Esc 收起。760px 及以下列表占满页头下方的可用宽度，顶部按钮仍可开关。点击资产进入详情后，列表按钮取消 active；关闭详情不会再次展开列表。下述可调宽及全屏规范适用于资产详情。

### 7.1 容器（已确认方向，尺寸为本轮采用值）

- 从页面顶部附近展开，覆盖右侧 Header 所在区域。
- 上下及外侧保留小间距，呈现一张独立的白色面板。
- 面板顶部留 **8px**；策略与 Replay Header 均高 **44px**，聊天 Header 保持 **48px**。策略单行摘要标题可整体切换版本，见 §7.3。
- 常规分栏及窄屏覆盖详情面板上、右、下保留 **8px** 外边距，左侧分栏间隔保持 **4px**，桌面四角 **14px** 圆角，窄屏 **12px**。点击全屏后，Strategy / Replay 详情移至页面顶层，覆盖整个浏览器视口（包括侧栏和页头），无外边距、圆角、边框或阴影；退出全屏恢复原分栏宽度和阅读位置。
- Esc 逐层返回：菜单/弹窗 → 退出主动全屏 → 关闭侧栏详情。每次按键只处理一层，长按不继续关闭；全屏退回半屏后保留内容和焦点，右上角关闭按钮仍直接关闭详情。
- 桌面直接拖动面板左边框调整宽度，不另加分隔线。悬停时立即显示垂直居中的浅色短竖线，按下拖动后颜色加深并保持显示，松开恢复浅色。鼠标位置左侧的提示延迟 **400ms** 出现；离开或开始拖动时取消延时并隐藏提示。保留键盘调整能力。
- 面板本身滚动，圆角边界应保持完整。
- 与聊天画布使用轻边框和极弱阴影区分，不增加厚重装饰。

### 7.2 回测内容与交互基线

本版本不开放洞察：不请求洞察接口，不展示图表/时间轴洞察点、图例、浮层或手机洞察页签、内容及相关追问。手机直接展示交易区域，行情、成交和交易定位追问保持可用。

**版本边界：** Runtime v1/v2 保留既有历史指标口径。Runtime v3 桌面和手机顶部前五项组合指标及历史指标详情随统一时间轴更新，第六项年化 Sharpe 固定显示完整回测结果；历史阶段标题为“截至此时”，末端为“最终结果”并采用服务端最终结果，切换图表标的或查看周期不改变组合统计。共享账户资金与全标的交易按同一截止位置计算，不把单腿收益或仓位当成组合结果。所有版本顶部统一六项指标，不展示“当前持仓”，详情中的账户与持仓信息保留原口径。行情、交易和事件随同一截止位置揭示。

- 回测标题下拉所有选项采用相同两行布局：名称、交易对 / 周期 / 回测起始日期；v3 标的摘要列出冻结集合，不能只用第一腿代表策略；始终按回测创建时间逆序排列。选中项保留相同信息与尺寸，仅以勾选标记区分，不置顶。

- 回测内容滚动容器使用 `scrollbar-gutter: stable`，半屏及全屏均预留原生滚动条宽度，避免内容增减触发滚动条显隐时挤动图表与时间轴；覆盖式滚动条按系统行为显示。

- 桌面首次打开采用默认缩放：目标之前约 100 根 K 线、右侧 8 根宽度。无论从头播放、中途定位或回到最新，都按当前用户缩放判断已揭示历史是否铺满一屏：不足时首根靠左，K 线向右增长，填至默认右侧边距后自动跟随；保留用户已调整的 K 线宽度。进度条原生 range 的空白点击/拖动/键盘操作只切换历史时刻：暂停、清除旧框选和交易选中态，保留用户 K 线宽度，历史不足一屏时采用上述左侧增长布局，铺满时将最后一根可见 K 线平移到绘图区约 93% 处，右侧约 7% 留白。保留查看周期，未来行情与交易隐藏，顶部指标同步截止位置。播放从该时刻继续时仍保留缩放。主轨道与折叠浮层的成交圆点采用独立成交定位：清除旧交易选择，仅在成交时间显示一根 1px 细竖线，不联动选中交易、不展开交易列表，不绘制整根 K 线区间、双竖线或成交价/进出场价格线。保持时间轴截止点与播放状态，跨标的时切换到对应图表，保留目标图表当前周期与缩放，仅水平平移成交至实际绘图区 50% 正中，已可见或重复点击时也居中；TAG 不增加定位动效。结果定位复用交易卡片的框选与条件平移，不自动缩放。桌面底部交易卡片保留用户当前缩放：框选后仅在区间末端不可见时平移，长区间可超出视野。再次点击已选中的交易卡片取消选中并移除框选，仅清除标记，保持位移、缩放、查看周期、播放进度和跟随状态；鼠标及键盘激活一致。

桌面回测控件不显示鼠标或键盘焦点外框，保留原有选中态。点击时间轴定位后可直接按空格播放/暂停，焦点无需转移到播放按钮；长按空格不连续切换，不滚动页面。输入框、菜单和阅读层不接管空格。此规则仅作用于回测工作区，手机保持原行为。

- 半屏、调宽、全屏及手机均以全宽 K 线为主体。
- 一个历史截止位置决定可见范围，没有浏览/播放模式切换。默认末根；拉回过去同时隐藏未来行情与成交，暂停保持边界，播放从当前处继续。拉到末根即可查看全程。
- 所有版本顶部统一展示净收益率、最大回撤、交易笔数、胜率、盈亏因子、年化 Sharpe 六项，桌面六列按内容宽度均匀分布，末列标题和数值右对齐图表右边界；“查看详情”取消右侧内边距，与末列共用右边界。桌面数值为 400 普通字重，净收益率不单独放大，所有指标统一 18px，窄容器统一 16px。结果标题采用纯文字：历史位置为品牌色“截至此时”，末端为弱化文字色“最终结果”；不使用图标、底色或胶囊外形，布局保持一致。图下不重复展示状态行，账户、仓位和浮动盈亏保留既有详情与状态入口，指标网格不再放孤立箭头。手机以三列两行展示相同六项。前五项保持既有历史指标口径：v1/v2 桌面随时间轴更新，v3 桌面与手机随统一时间轴展示组合统计；年化 Sharpe 始终固定。“查看详情”保留对应历史阶段的账户与统计信息，不展示基准腿仓位作为全局持仓。
- 回测详情头部只保留查看策略、全屏、关闭操作，移除更多按钮及其下拉菜单。运行包下载统一从策略详情头部进入，未具备下载来源时禁用。
- 桌面日期与条件入口并入标的/策略元信息首行，窄面板日期允许省略并通过悬停显示完整日期。v3 条件阅读层逐项列出标的、市场与只读用途。

### 7.3 策略详情

策略 Header 高 44px，左侧单行变更摘要与上下箭头组成一个整体单选入口，右侧保留全屏和关闭。入口桌面高 30px、小屏 36px，最大宽度 560px，并随可用空间收缩；标题 14px / 20px，长摘要单行省略。默认无边框和底色，悬停及展开时整个区域使用中性浅底，键盘聚焦有清晰轮廓，点击标题或箭头均打开同一下拉。折叠标题与下拉选项均优先 `change_summary`，缺失才回退到策略名；策略名放在下拉辅助行和悬停提示中。完整摘要可在下拉或提示中阅读，不增加副标题或正文重复摘要；标题提示与辅助技术描述保留当前标识/本地形成时间。

## 8. 动效与形状

已确认原则：**克制但不死板。**

当前原型可参考的反馈：

- 研究 / 消息输入框沿用普通细边框，聚焦不变为赭金；此项以当前实现为准。
- 主按钮悬停略加深，按下有轻微缩放。
- 快捷示例卡片不使用位移动效，仅保留 §6.4 定义的轻量颜色反馈。
- 过程展开、面板出现、事件选中有短促、可理解的变化。
- 支持 `prefers-reduced-motion`，减少非必要运动。

列表与详情分别使用 `--motion-asset-list` / `--motion-asset-detail`，当前均继承 `--motion-panel`（260ms），后续可独立调整：展开从右向左滑入，收起反向滑出，关闭动画结束后再隐藏；桌面正文空间同步过渡，面板内容保持目标宽度，避免反复折行。列表卡片与聊天卡片打开详情时，均由详情组件执行同一段从右向左的滑入；原列表独立向右收起，不先把聊天恢复全宽，也不在窄列表里直接替换详情内容。边框调宽不带缓动；全屏和小屏沿用同一方向，减少动态效果偏好下跳过过渡。其余控件复用全局动效变量。不要通过长动画、重复脉冲、收益庆祝效果或持续旁白增加噪声。

## 10. 正式产品仍需打磨的内容

1. **深色主题**：未来完成深色配色并正式开放深色与跟随系统；目前仅浅色完成方向探索，工程开关下可选的 `.dark` 样式不代表已设计的深色方案。
2. **字体与可读性**：中英文字体一致性、字体授权、文字对比度、小字号、缩放和不同平台表现。
3. **组件完整状态**：Hover、Focus、Active、Disabled、Loading、空态、错误、重试与网络中断。
4. **真实流式对话**：首字、停止、失败、断线恢复、工具事件、滚动跟随和用户主动浏览历史的关系。

8. **数据语义**：真实费用、数据区间、延迟、风险及验证来源，不能用演示数字支撑真实结论。
9. **代码与验证**：组件拆分、统一设计 token、浏览器交互验证和无障碍验证。当前通过构建及类型检查，并不等于完成全面视觉与交互验收。
