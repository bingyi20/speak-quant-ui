# 策略详情模块技术方案

更新：2026-09-16。实现入口见[架构代码索引](Trade%20Lab%20前端整体架构方案.md#53-代码索引地图)，验证范围见[Agent 对话接口联调记录](Agent%20对话接口联调记录.md#策略详情与回测列表联调2026-09-15)。

## 1. 内容与范围

用户界面统一使用“回测 / Backtest”，记录列表使用“回测记录 / Backtests”，遵循[产品术语](产品决策.md#产品术语)。本文的 Replay 指该回测对象；API 路径、字段、事件、类型、组件与国际化键名仍沿用 Replay，不改动既有接口契约。

复用右侧资产详情面板。Header 左侧以所选节点的单行变更摘要作为整体版本切换入口，右侧为全屏和关闭。移除返回资产列表的常驻按钮。主体为设计（中文）/ Design（英文）、回测记录、代码三个 Tab；切换版本同时切换三者，保留所在 Tab。版本切换仅查看，不执行恢复、修改或回测。

聊天和资产列表中的 Strategy 入口始终打开当前策略；当前与历史版本以真实 `current_node_id` / 历史节点 ID 关联，不把内部 `revision` 生成为 V1/V2。版本选择复用 `USelect` 单选控件（combobox / listbox）。折叠与展开均以所选节点的 `change_summary` 为主，策略名为次级信息。折叠标题显示单行摘要与上下箭头，整个标题是同一个点击目标，长摘要省略，完整内容可在下拉或悬停提示中阅读；缺少摘要才回退到策略名。策略名显示在下拉辅助行和标题提示中，不增加标题副行或正文重复摘要。标题提示与辅助技术描述按摘要、名称、当前标识/本地形成时间的顺序展示，Heading 也引用所选摘要。选中后标题与设计、代码、回测同步切换。所有版本在同一下拉列表，当前策略固定首项，不再标注“当前”。主行摘要统一左对齐，次行左侧为单行策略名，右侧轻量显示本地月/日与时分，完整年份和时间放在时间的悬停提示中；当前项读取 `updated_at`，历史项读取 `formed_at`。回测状态与次数由详情承载，不在选择器重复展示。选中项用右侧勾选标识，所有项预留相同勾选空间，仅悬停/键盘焦点时出现浅底，无前置徽标、卡片分组或分隔线。旧历史无摘要时以名称为主、本地形成时间为次级信息，不重复名称或增加缺失提示。当前已验证节点不在历史项中重复展示。历史加载失败的重试按钮单独放在下拉底部，不混入版本选项。

Design 与 Agent 正文共用 `MarkdownContent` 渲染器和 `markdown-prose` 排版样式，统一桌面/小屏字号、行高、标题、段间距、引用与代码块。正文先展示 Markdown 内容，末尾右侧提供原始 Markdown 复制；仅当前状态为 modified 时，在末尾左侧轻量显示“修改后未回测”，不在标题前堆放状态或操作。代码展示接口返回的单个入口文件，按所选版本读取，支持 Python 语法高亮、行号、横向滚动与复制；没有入口代码时显示简短空态。代码只留在当前面板内存，不写入浏览器持久存储或日志。

## 2. 回测范围

默认按所选策略节点过滤，紧凑记录列表展示回测名称、标的、周期、区间、净收益率、最大回撤和交易次数。点击一行打开同一 Replay ID 的详情。无交易结果仍是有效记录，显示“无交易”和实际零值；缺失指标显示 `—`。

“查看所有回测”只扩大回测列表范围，不改变 Header 版本及 Design/代码。全部模式优先用节点摘要显示各记录所属版本，缺少摘要时回退到名称；所属版本与回测名称同行，过长省略、悬停可查看完整摘要，不增加记录高度；属于所选节点的记录只显示高亮“所选版本”标记，不改变整行背景。列表不显示右侧箭头，保留整行点击与悬停反馈，提供“仅看所选版本”切回。按创建时间倒序，不按收益评定最佳策略。

| 操作 | 列表范围与位置 |
| --- | --- |
| 从卡片打开或重新打开策略 | 当前策略，所选版本范围 |
| 切换 Header 版本 | 新选版本范围，滚动回顶部 |
| 从 Design/代码切回回测 | 所选版本范围，滚动回顶部 |
| 切换全部/所选范围 | 用户指定范围，滚动回顶部 |
| 进入 Replay 再返回 | 保留版本、范围、滚动位置和原行焦点 |
| 关闭详情 | 关闭面板，不重新打开资产列表 |

未回测修改、草稿、恢复后未回测且没有 `current_node_id` 时，所选范围为空；仍可点击“查看所有回测”。不将来源历史回测当作当前代码的结果。

## 3. HTTP 与状态

- `GET /conversations/{id}/strategy`：当前 Design、Code 和**整个会话**已完成的 Replay 概要；`current_node_id` 决定当前范围。已核对真实响应和后端实现。
- `GET /strategies/{id}/history?page&size`：按实际 `total_pages` 读取版本菜单，去重，不把第一页当完整历史。失败保留当前内容，通过菜单重试。
- `GET /strategy-nodes/{id}`：历史版本冻结的名称、摘要、Design、Code 和 Replay 概要。
- `GET /replays/{id}`：对应 Replay 的条件、核心指标和后端提供的结论。

当前、历史列表和节点详情读取 `change_summary` / `change_base_node_id`，兼容旧接口或旧记录字段缺省/null。摘要由后端维护，覆盖相对上一已回测节点的累计变化；前端不从名称、时间或最后一条消息推导摘要，始终以节点 ID 选择。同名、同摘要节点也不合并。

所有请求经现有 `$http`；URL 和 DTO 位于所属模块，不增加 BFF、请求缓存或持久化 store。`detail-state.ts` 管理当前/历史选择与范围；composable 按登录用户、会话和面板生命周期取消请求。切换版本、重新打开、切换账户、卸载时取消旧请求并拒绝迟到写回；加载中不把旧版本正文挂在新标题下。Agent Run 从活动态结束后刷新已打开的详情。

会话标题在首轮终态前由后端独立生成，沿用现有终态刷新 Conversation 详情/列表流程。前端不从策略名推导或覆盖会话标题。

## 4. Replay 跳转边界

完整回测工作区见[回测详情模块技术方案](回测详情模块技术方案.md)。来源策略 controller 持续保留版本、回测范围与滚动；回测“查看策略”使用独立 controller 的 initialNode 读取冻结 node_id，返回恢复原回测并保持暂停。导航保持一层来源，不递归堆叠详情。

策略列表和独立 Replay 卡片共用 `ReplayDetailContent`，提供冻结条件、完整结果、K 线、Timeline、播放、洞察与交易明细。只消费服务端返回数据；真实接口与模拟验证范围见[回测详情联调记录](回测详情联调记录.md)。

仅从策略列表进入 Replay 时显示“返回策略”图标；独立打开策略或 Replay 都没有无意义的返回按钮。桌面调宽与全屏状态在内部跳转期间不变，策略列表保留挂载以恢复滚动与焦点。全屏通过 Teleport 将同一详情 DOM 移到 body，铺满整个视口且无圆角；退出时移回分栏，保留版本、Tab、滚动及焦点。版本菜单通过控件 Portal 挂到 body，Popper 层级高于全屏面板，避免菜单已打开却被面板遮挡。全屏期间工作台 inert，焦点约束通过详情 ID 跨 Teleport 定位；关闭和卸载恢复背景交互。Replay 接口失败就地重试；执行中、失败和取消展示实际状态。

## 5. 布局与验证约定

尺寸、颜色及窄面板表现由[浅色版设计决策](Trade%20Lab%20浅色版设计决策.md#73-策略详情)维护。基础数值格式复用 Decimal Formatter；中英文系统文案同步维护。代码高亮只加载 highlight.js core 与 Python 语法，异步加载代码组件，输出经过清洗，不执行策略代码。

单测覆盖节点归属、迟到响应、清理、历史分页/失败和范围重置；模拟浏览器覆盖版本联动、空态、Replay 往返、Header、复制、版本选择器键盘和桌面/手机布局。真实联调仅只读检查已有研究，不为制造测试状态修改用户策略。

## 6. 运行包下载

策略详情头部统一提供“下载运行包”图标，复用 RunnerDownloadDialog。下载来源限定为所选冻结节点最近一条 traded/no_trades 回测（按 created_at、id 降序），不受“查看所有回测”范围影响；无节点或有效回测时禁用，草稿不能借用旧版本记录。当前版本、历史版本及从回测进入的关联策略使用同一规则。弹窗显示来源并允许选择平台和架构，复用现有真实下载接口；切换版本、关闭面板或返回回测时关闭弹窗并取消未完成请求。回测详情不再提供更多菜单、报告或下载入口。
