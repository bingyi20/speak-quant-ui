---

## 1. 文档目的

本文档是 Trade Lab MVP 唯一的详细交互方案，用于统一定义各模块的页面布局、操作路径、状态切换、反馈、异常、响应式行为与交互验收标准。

本文档描述产品应呈现的行为，不规定图表库、数据结构、播放器实现或其他技术方案。

所有 MVP 模块的详细交互持续追加到本文档，不再为单一模块创建独立交互方案。总 PRD 负责定义业务需求与产品边界，本文档负责说明用户如何操作以及界面如何响应。

---

## 2. 文档结构与维护规则

本文档按用户体验模块组织，模块之间共享统一的 Conversation、右侧资产面板和导航状态。

当前交互范围：

1. 全局产品框架与导航
2. Landing / New Conversation
3. Login
4. Replay Workspace
5. Runner 下载入口

Agent Conversation 沿用成熟对话产品交互；Strategy 详情、历史切换与恢复直接按总 PRD 出设计稿，不在本文档重复描述。

维护规则：

- 已确认交互直接写入对应章节。
- 尚未确认的内容标记为“待讨论”，不写成最终规则。
- 跨模块的相同状态只定义一次，其他章节通过引用避免重复或冲突。
- 每轮交互讨论结束后同步更新本文档、总 PRD 和必要的产品决策。

# Part A：全局产品框架与导航

## A1. 设计结论

Trade Lab MVP 直接沿用 Claude / ChatGPT 已被用户熟悉的 Agent 产品交互框架：

- 左侧可收起导航栏
- 新研究入口
- 收藏 Conversation 与全部 Conversation
- 中央 New Conversation / Agent Conversation
- 底部固定对话输入框
- 当前 Conversation 的右侧资产入口

不为 Trade 场景重新设计交易终端式全局框架。Trade Lab 的产品差异集中体现在 Strategy、Agent 协作式回测、动态研究过程、Replay 和 Runner，而不是全局导航。

本方案借鉴成熟产品的交互心智，不复制其品牌标识、视觉资产或具体样式。

## A2. Desktop 全局布局

```text
┌───────────────┬──────────────────────────────────────────────────────┐
│ Trade Lab     │                                               资产   │
│               │                                                      │
│ ＋ 新研究      │                                                      │
│               │                 中央主内容区域                        │
│ 收藏          │                                                      │
│ Conversation ⋯│         New Conversation / Conversation             │
│               │                                                      │
│ 全部          │                                                      │
│ Conversation ⋯│                                                      │
│ Conversation ⋯│                                                      │
│               │                                                      │
│ 账户 / 用量   │                                                      │
└───────────────┴──────────────────────────────────────────────────────┘
```

全局采用三层结构：

1. 左侧：Conversation 导航
2. 中央：新研究或当前 Agent Conversation
3. 右侧：当前 Conversation 的 Strategy / Replay 资产面板

右侧资产面板默认关闭，不长期占据中央对话空间。

## A3. 默认进入 New Conversation

用户登录后每次重新进入产品，默认打开空白 New Conversation，不自动进入最近 Conversation，也不默认展示资产 Dashboard。

首页只承担一个核心任务：

> 输入一个交易想法并开始研究。

首页不展示：

- 实时行情
- 币价涨跌榜
- 市场热力图
- 当前持仓
- 历史收益 Dashboard
- 全局 Strategy 列表
- 全局 Replay 列表
- Runner 运行状态

历史研究通过左侧 Conversation History 进入。

## A4. New Conversation 页面

```text
┌──────────────────────────────────────────────────────────┐
│                                                          │
│                       Trade Lab                          │
│                                                          │
│              3 分钟，验证你的交易想法                    │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 描述你的交易想法……                                 │  │
│  │                                                    │  │
│  │                                                ↑   │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  快速开始                                                │
│  [趋势跟随]  [放量突破]  [均值回归]  [多周期策略]        │
│                                                          │
│       历史结果不代表未来表现 · 不构成投资建议             │
```

### A4.1 输入框

- 使用大型多行输入框。
- 右下角使用仅含向上箭头的圆角方形发送按钮。
- 空输入时按钮不可用。
- 支持键盘快捷提交和换行。
- 输入内容在登录、刷新或返回后不能丢失。
- Placeholder 使用自然语言示例，不要求用户填写结构化表单。

### A4.2 Quick Examples

输入框下方展示最多 4 个真实策略示例：

- 趋势跟随
- 放量突破
- 均值回归
- 多周期做多 / 做空

Quick Examples 用于提供可编辑的策略输入，不用于介绍产品功能。

点击示例后：

- 将完整示例填入输入框。
- 不立即提交。
- 用户可以继续修改。
- 输入框获得焦点。

不使用“创建策略、运行回测、查看 Replay、生成 Runner”等产品功能卡作为 Quick Examples。

### A4.3 Conversation 创建时机

- 点击“新研究”只打开空白 New Conversation。
- 用户第一次发送有效内容后才正式创建 Conversation。
- 没有发送内容的空白页面不进入 Conversation History。
- Conversation 标题在首次有效交互后由 AI 根据研究想法生成。

## A5. 左侧导航栏

### A5.1 顶部固定区

- Trade Lab Logo / 名称
- “＋ 新研究”
- 收起 / 展开侧栏

用户在任何页面点击“新研究”后进入空白 New Conversation，不删除或修改当前 Conversation。

### A5.2 Conversation History

Conversation History 只包含两个列表：

1. **收藏**
2. **全部**

- “收藏”展示用户已经收藏的 Conversation，按最近更新时间倒序。
- “全部”展示全部 Conversation，按最近更新时间倒序。
- 已收藏的 Conversation 同时保留在“全部”列表中；收藏区是快捷入口，不是从全部列表移动出来的独立目录。
- 没有收藏内容时，收藏区可以折叠或展示简洁空状态。

每条记录以 Conversation 标题作为主要信息，右侧固定提供三点菜单。MVP 不在左侧直接展示：

- Strategy 状态
- Replay 数量
- 回测收益或回撤
- Runner 状态
- 版本号
- “正在使用”等标签

点击一条历史记录后，恢复完整 Conversation、当前 Strategy 状态和对应右侧资产上下文。

点击 Conversation 右侧三点菜单后展示：

- 收藏状态切换：“收藏”或“取消收藏”
- 重命名
- 删除

菜单规则：

- 点击菜单外区域、按 Esc 或完成操作后关闭。
- 收藏状态切换后立即更新收藏列表，不影响全部列表的位置和排序。
- 重命名进入就地编辑或轻量弹窗；保存后两个列表中的标题同步更新。
- 删除属于不可恢复操作，必须展示二次确认弹窗。

删除确认必须说明：

- Conversation 删除后不可恢复。
- 该 Conversation 下的当前 Strategy、历史策略节点、Conversation History 和全部 Replay 将一并删除。
- 已经下载到用户本地的 Runner 包不受影响。

确认按钮使用明确文案“永久删除”，不使用含糊的“确定”。取消是默认安全操作。

### A5.3 底部固定区

账户入口固定放在左侧导航栏底部，不放在产品右上角。底部可以包含：

- 用户头像、名称或邮箱
- 帮助
- 语言
- 设置

不向用户展示 Token。

### A5.4 收起状态

侧栏收起后只保留：

- Logo
- 新研究
- 展开按钮
- 用户头像

收起和展开不改变中央 Conversation 的滚动位置，也不关闭已经打开的右侧资产。

## A6. 中央 Conversation

进入历史 Conversation 后，中央区域使用标准 Agent 对话结构：

- 用户自然语言消息
- AI 文本回复
- Clarify 快捷选项
- Strategy 生成 / 更新摘要
- Replay 执行状态卡
- 动态研究过程
- Replay 卡片
- Runner 相关操作卡

普通文本保持舒适阅读宽度；Strategy 和 Replay 等结构化卡片可以使用更宽内容区域。

底部输入框固定：

- 支持继续修改当前 Conversation 唯一对应的 Strategy。
- 用户正在查看右侧 Strategy 或 Replay 时仍可继续对话。
- 从 Replay 洞察发起追问时，将对应 Replay 与时间位置带入对话上下文。

## A7. 顶部栏

顶部栏保持克制，只提供当前场景必要操作。

New Conversation：

- 侧栏展开 / 收起

历史 Conversation：

- 侧栏展开 / 收起
- Conversation 标题
- 当前 Conversation 的资产入口

MVP 不提供复杂的一级导航、行情频道或多个 Workspace Tab。

## A8. 右侧资产入口

当前 Conversation 形成 Strategy 后，顶部右侧显示资产入口。点击后打开该 Conversation 的统一资产列表：

1. 第一张固定为当前 Strategy。
2. 下方展示“回测记录 · N”及全部 Replay。

右侧面板规则：

- 默认关闭。
- 资产列表使用较窄面板。
- 打开 Strategy 或 Replay 详情后扩展到右侧约 50%。
- 中央 Conversation 与右侧详情之间的分隔线可拖动。
- 同时只打开一个资产详情。
- 关闭后中央 Conversation 恢复主要空间。
- New Conversation 尚未形成 Strategy 时不展示资产入口或使用不可执行的弱状态。

Replay 新生成后可以自动打开右侧 Replay Workspace。该行为不改变左侧 Conversation 的选择和中央 Conversation 的滚动位置。

## A9. 视觉方向

全局视觉保持安静、清晰、可信，避免通过交易终端元素制造专业感。

不采用：

- 首页实时行情和闪烁价格
- 大面积红绿涨跌色
- 订单簿式信息密度
- 赛博朋克霓虹
- 交易所式复杂导航

Trade Lab 的研究感通过以下部分形成：

- Strategy 和 Replay 的差异化资产结构
- 清晰的已验证 / 未验证状态
- Agent 回测与研究过程
- K 线、Timeline 和 AI 洞察
- 精确、易比较的价格、时间和指标数字

全局框架的熟悉度优先于装饰性创新；核心研究体验的辨识度优先于首页“酷感”。

## A10. H5 与响应式原则

Desktop：

- 左侧导航 + 中央 Conversation + 可选右侧资产。

H5 是 Trade Lab MVP 的主要获客入口，不是只读兼容版本。H5 必须完整支持：

- Landing 与 Quick Examples
- 输入策略并在登录后恢复原始内容
- Login
- Clarify
- Agent 发起回测与必要的 Clarify
- Conversation 动态过程
- Strategy 查看
- Replay 查看与核心交互
- 基于洞察继续询问 Agent
- 修改 Strategy 并发起下一次回测

### A10.1 H5 全局框架

- 页面默认只显示中央 New Conversation 或 Conversation。
- 左上角使用菜单按钮打开侧栏抽屉。
- 侧栏抽屉展示“新研究、收藏、全部、账户”。
- 账户入口固定在抽屉底部。
- 抽屉打开时不丢失当前输入、Conversation 滚动位置或 Replay 状态。
- 选择 Conversation 后自动关闭抽屉并进入目标会话。
- Conversation 三点菜单使用适合触控的操作菜单或 Bottom Sheet。
- 所有关键点击区域满足触控尺寸，不能依赖 Hover 才能发现。

### A10.2 H5 New Conversation

- 标题、输入框和 Quick Examples 适应单列布局。
- 输入框保持页面核心视觉位置。
- Quick Examples 可以横向滑动或使用紧凑两列布局，不占满首屏。
- 移动键盘弹出时，发送按钮保持可见。
- 登录中断后必须恢复用户原始策略输入。

### A10.3 H5 Conversation

- 底部输入框固定，并适配设备安全区域与移动键盘。
- Strategy 卡和 Replay 卡使用单列宽卡。
- 当前 Conversation 的资产入口放在顶部右侧。
- 点击资产入口后以全屏层打开资产列表，而不是在小屏并排挤压 Conversation。
- 关闭资产层后恢复 Conversation 原滚动位置。

### A10.4 H5 Replay

- Replay 在 H5 使用全屏 Workspace，不与 Conversation 左右并排。
- K 线仍是视觉主体。
- Timeline 保持固定完整区间，可触控拖动。
- AI 洞察使用底部抽屉或独立层展开。
- 用户可以返回 Conversation，返回 Replay 时恢复时间位置和选中洞察。
- H5 必须支持整体预览、首次快速回放、暂停、拖动 Timeline、退出回放和点击洞察定位。

Desktop 和 H5 共享相同业务状态与资产，不形成两套产品逻辑。布局可以不同，但关键操作和研究结论必须一致。

## A11. 全局框架验收标准

- 用户每次进入产品默认可以立即输入新的交易想法。
- 未发送的空白 New Conversation 不进入历史。
- 左侧只承担 Conversation 导航，不演变为 Strategy 资产管理器。
- 用户可以从历史 Conversation 恢复完整研究上下文。
- 用户可以通过收藏快速访问 Conversation，全部列表始终按最近更新时间倒序。
- 每条 Conversation 的三点菜单可以切换收藏、重命名和永久删除。
- 永久删除必须二次确认并明确不可恢复。
- 用户查看 Strategy 或 Replay 时仍能继续与 Agent 对话。
- 右侧资产只属于当前 Conversation。
- 首页不因交易场景增加实时行情或复杂 Dashboard。
- Quick Examples 可以一键填入并继续编辑，不会自动提交。
- 侧栏和资产面板的开关不丢失 Conversation 与 Replay 状态。
- 账户入口只位于左侧导航底部或 H5 侧栏抽屉底部，不出现在产品右上角。
- H5 可以完整完成从输入策略到查看 Replay、追问洞察和再次回测的核心闭环。

# Part B：Replay Workspace

## 3. Replay 的产品定义

Replay 是一次回测完成后形成的只读实验资产，同时承载：

- 完整回测结果
- 历史 K 线和策略交易节点
- 策略决策过程
- 可定位的 AI 洞察
- 回测条件、交易记录与研究结论

Replay 的核心定位是：

> **一份可播放、可定位、可解释、可追溯的策略实验报告。**

Strategy 说明“策略准备如何交易”；Replay 证明“策略实际上如何交易，以及为什么”。

Replay 不是：

- 用于隐藏未来行情并训练用户主观交易能力的练盘工具
- 允许用户手动模拟下单的交易模拟器
- 单纯逐根播放 K 线的视频
- 只有收益指标和买卖箭头的传统回测报告
- 可以被修改、覆盖或恢复的策略实体

---

## 4. 核心价值

Replay 需要帮助用户完成四件事：

### 4.1 检查可信度

用户可以检查策略在某个时刻看到了什么条件、为什么交易、如何改变仓位，以及费用、止损、止盈或强平如何影响结果。

### 4.2 理解决策过程

Replay 将一次交易还原为：

`市场状态 → 规则满足 → 策略决策 → 仓位变化 → 交易结果`

### 4.3 发现策略问题

用户可以快速定位最大亏损、最大回撤、连续亏损、异常交易、失效区间和成本侵蚀。

### 4.4 进入下一轮研究

用户从 Replay 中发现问题后，可以回到 Agent 提出修改，形成新的 Strategy 状态并再次回测。

Replay 的终点不是“播放结束”，而是产生新的研究行动。

## 5. 页面结构

### 5.1 宽屏 / 全屏布局

```text

│                                              │ 关键交易               │
```

### 5.2 空间优先级

1. K 线是页面最大视觉主体。
2. AI 洞察辅助解释 K 线，不得压缩 K 线成为次要区域。
3. 顶部只固定展示最关键的完整回测指标。
4. Timeline 高度固定，不展示视频缩略图或 K 线预览。
5. 详细指标、交易记录、策略规则和回测条件采用按需展开。

## 6. 两种核心模式

Replay Workspace 包含两种明确模式：

1. **整体预览**
2. **回放模式**

产品必须通过模式名称、Timeline 样式和控制栏变化让用户知道当前处于哪种模式，不能只通过“未来 K 线是否消失”暗示状态。

### 6.1 模式状态关系

```text
整体预览
  ├── 点击“进入回放” → 回放模式
  ├── 点击 Timeline / Marker → 完整行情定位
  └── 点击 AI 洞察 → 完整行情洞察定位

回放模式
  ├── Play / Pause / Speed → 推进回放
  ├── 拖动 Timeline → 改变回放时刻并保持暂停
  ├── 点击 AI 洞察 → 暂停并进入整体预览定位
  ├── 点击“退出回放” → 整体预览并保留当前时间位置
  └── 播放结束 → 自动进入整体预览
```

## 7. 整体预览

### 7.1 目的

整体预览用于快速理解完整实验结果、自由查看历史行情、检查交易、阅读洞察和进入下一步研究。

### 7.2 K 线行为

- 完整回测范围的数据均已存在，不隐藏所选时刻之后的 K 线。
- 用户可以缩放和平移 K 线视图。
- K 线缩放只改变图表视野，不改变 Timeline 的长度、日期范围或 Marker 位置。
- 点击 Timeline 日期或事件 Marker 后，将对应时刻移动到 K 线视图中央附近。
- 若定位目标是一个时间区间，自动调整 K 线视野，使目标区间完整可见。

### 7.3 Timeline 行为

整体预览中的 Timeline 是历史定位器：

- 点击任意位置，定位到对应历史时间。
- 拖动定位点，连续改变 K 线视图的中心时间。
- 松开后保留定位状态。
- 不隐藏该时刻之后的 K 线。
- 点击 Marker 精确定位到对应交易或关键事件。

### 7.4 主要操作

- 进入回放
- 查看洞察
- 查看交易记录
- 查看本次使用的 Strategy
- 生成 Runner 下载包
- 返回资产列表

---

## 8. 回放模式

### 8.1 目的

回放模式用于还原策略在历史时间推进过程中如何形成信号、做出交易和产生结果。

回放强调策略决策，不要求用户手动交易，也不通过禁止查看完整结果制造练盘场景。

### 8.2 进入回放

用户可以通过以下方式进入：

- 点击“从头回放”
- 从当前 K 线位置开始回放
- 从某条洞察或关键事件之前开始回放
- 新 Replay 生成后首次自动打开

MVP 主入口为“从头回放”。“从当前时刻开始”和“从事件前开始”可作为次级入口。

### 8.3 K 线行为

- 当前回放时刻之后的 K 线隐藏。
- K 线按时间顺序出现。
- 用户仍可以缩放当前已出现的 K 线视图。
- K 线缩放不改变 Timeline。
- 当前最后一根 K 线尽量位于图表横向约 70% 的位置，右侧保留观察空间。
- 进入关键事件时，高亮相关 K 线、Marker、价格、仓位和规则状态。

### 8.4 播放节奏

回放逻辑上从回测起点开始，但不逐根匀速播放全部历史：

- 无交易或无重要状态变化的长区间快速通过。
- 接近交易信号形成时降低速度。
- 开仓、平仓、止损、止盈、强平和关键异常时短暂停留。
- AI 当前事件解释完成展示后继续。
- 用户主动操作时立即取消自动继续。

### 8.5 回放控制

回放模式至少提供：

- 退出回放
- 从头开始
- Play / Pause
- 上一个关键事件
- 下一个关键事件
- Speed
- 当前回放时间

逐根前进可以作为次级控制，不作为 MVP 的核心主操作。

### 8.6 拖动回放进度

Trade Lab 允许用户在回放中自由拖动到任意历史时刻：

- 拖动时展示准确日期和时间 Tooltip。
- K 线随拖动进度快速更新。
- 松开后以该时刻为新的回放截止点。
- 该时刻之后的 K 线继续隐藏。
- 松开后保持暂停，用户主动点击 Play 才继续。
- 支持向前或向后拖动。

这与 TradingView 的手动练盘限制不同。Trade Lab 的目标是提高实验检查效率，而不是防止用户看到已知的历史结果。

### 8.7 退出回放

用户中途退出时：

- 所有未来 K 线恢复。
- 页面切换为整体预览。
- K 线继续定位在退出时刻，并将该时刻移动到视图中央附近。
- Timeline 恢复整体预览样式。
- AI 保留当前事件解释。
- 顶部完整回测指标不发生变化。

播放自然结束时：

- 自动退出回放并恢复完整 K 线。
- 保留回测末端的图表位置。
- AI 区域回到整体结论和本次研究建议。

## 9. Timeline

### 9.1 定义

Timeline 是映射完整回测区间的固定长度日期标尺和事件导航器。

它不展示视频缩略图，不展示 K 线预览，不承担图表缩放功能。

### 9.2 固定范围

- Timeline 始终从本次回测数据开始时间映射到结束时间。
- Timeline 不支持缩放。
- K 线图缩放、平移和可视 K 线数量不会改变 Timeline。
- 日期刻度根据回测跨度自动选择日、周、月等合适粒度，但起止范围不变。

### 9.3 Timeline 内容

- 回测起止日期
- 自适应日期刻度
- 当前定位点或回放指针
- 开仓、平仓、减仓、止损、止盈、强平等 Marker
- Biggest Win、Biggest Loss、最大回撤区间等研究 Marker
- Marker 密集区域的聚合数量

### 9.4 两种模式的视觉差异

整体预览：

```text
01月 ─────●──────▲────────●────────────── 12月
                  当前定位
```

回放模式：

```text
已经发生                    尚未发生
██████████████████│░░░░░░░░░░░░░░░░░░
                  ▲
             当前回放时刻
```

整体预览中的定位点只负责导航；回放模式中的指针同时决定未来 K 线是否显示。

### 9.5 Marker 交互

- Hover 展示事件类型、日期、方向和简要结果。
- 点击后精确定位事件。
- Marker 密集时聚合，点击聚合后展示事件列表，不缩放 Timeline。
- 选中 Marker 时，K 线、交易标记、动态状态和 AI Explain 同步更新。

---

## 10. 顶部回测指标

### 10.1 固定展示完整结果

顶部核心指标始终展示完整回测结果，不跟随 Timeline 或回放进度变化。

建议固定展示：

- 净收益率
- 最大回撤率
- 交易次数
- 胜率
- Profit Factor 或盈亏比

顶部必须标记“完整回测”，避免用户将其误认为当前进度数据。

### 10.2 当前时刻动态状态

当前进度信息单独展示在 K 线与 Timeline 之间，并随定位点或回放指针变化：

- 当前日期和时间
- 当前仓位和方向
- 截至当前的累计收益
- 截至当前的回撤
- 当前持仓浮动盈亏
- 当前杠杆或强平距离（适用时）

用户可以展开查看更多状态，但动态信息不得取代顶部完整结果。

## 11. AI 洞察

### 11.1 洞察类型

AI 洞察至少分为：

- 整体结论
- 关键盈利与亏损事件
- 风险和失效区间
- 异常交易行为
- 改进机会
- 下一步研究建议

每条洞察包含：

- 简短结论
- 对应时间点或时间区间
- 支撑数据或交易证据
- 洞察类型
- 已验证结论或待验证假设标记

### 11.2 整体预览中的 AI

整体预览中的 AI 主要回答：

- 策略整体为什么盈利或亏损
- 哪些市场状态表现最好或最差
- 主要风险是什么
- 下一步值得验证什么

### 11.3 回放模式中的 AI

回放模式中的 AI 优先展示当前时刻解释：

- 哪些策略条件已经满足
- 哪些条件阻止交易
- 为什么开仓、平仓、止盈、止损或强平
- 仓位和风险如何变化
- 当前交易对最终结果的影响

普通 K 线期间不持续旁白。AI Explain 只在策略决策和关键状态变化时出现。

### 11.4 点击洞察

用户点击一条洞察后：

1. 暂停当前播放。
2. 进入整体预览。
3. 恢复全部历史 K 线。
4. 将对应时刻移动到 K 线视图中央。
5. 高亮对应 K 线、Marker 或时间区间。
6. Timeline 同步定位。
7. 洞察卡进入选中状态并展开证据。

如果洞察对应一个区间，图表应完整展示该区间。

界面提示：

> 已暂停回放，并在完整行情中查看该洞察。

洞察详情可以提供“从该事件前开始回放”，用于观察条件如何逐步形成。

### 11.5 与 Agent 的衔接

洞察详情提供：

- 询问 Agent
- 基于该发现提出修改
- 查看相关交易

从 Replay 发起的追问必须携带当前 Replay、时间点或区间、交易事件和关联历史 Strategy 上下文。对话回复仍出现在中央 Conversation。

## 12. 首次打开与再次打开

### 12.1 新 Replay 首次自动打开

回测成功后：

1. Conversation 输出 Replay 卡片。
2. Replay Workspace 自动在右侧展开。
3. 默认进入回放模式并定位到回测起点。
4. 页面短暂停留，让用户识别完整回测指标、K 线、AI 区域和 Timeline。
5. 自动开始快速回放。
6. 始终提供“直接查看结果 / 跳过回放”。
7. 关键事件自动减速或停留。
8. 播放完成后进入整体预览。

顶部完整回测指标在首次回放中仍然可见。Replay 不是结果竞猜或主观练盘，不需要隐藏最终指标。

### 12.2 再次打开历史 Replay

用户以后通过 Conversation 卡片、资产列表或 Replay 切换器重新打开时：

- 默认进入整体预览。
- 不自动重复播放。
- 提供“从头回放”。
- 若用户存在未完成的上次回放进度，可提供“继续上次回放”作为次级操作。

### 12.3 No Trades

No Trades Replay 首次打开时：

- 默认进入整体预览，不自动播放完整历史。
- AI 解释哪些入场条件从未满足。
- Timeline 标记最接近触发的阶段（能够确定时）。
- 用户仍可主动进入回放检查相关阶段。

### 12.4 用户跳过首次回放

点击“直接查看结果 / 跳过回放”后：

- 立即退出回放。
- 恢复完整 K 线。
- 进入整体预览。
- AI 展示整体结论。
- 本次 Replay 后续重新打开不再自动播放。

---

## 13. 响应式与右侧面板

### 13.1 默认半屏

Replay 默认在 Conversation 右侧约 50% 宽度打开。

- K 线优先占据可用宽度。
- AI 洞察在宽度不足时变为可收起的右下角抽屉。
- 抽屉收起时展示“AI 洞察 · N”及当前关键事件提示。
- 点击洞察或进入关键事件时可以半展开，不强制完全覆盖 K 线。
- 用户可以拖动 Conversation 与 Replay 之间的分隔线增加 Replay 宽度。

### 13.2 宽屏 / 全屏

宽度足够时：

- AI 洞察固定在右侧。
- K 线区域建议占主体宽度约 70%。
- AI 区域建议占约 30%，并设置合理的最小和最大宽度。

### 13.3 全屏与退出

- 全屏不改变当前模式、回放进度、K 线视野和选中洞察。
- 退出全屏后恢复此前半屏宽度。
- 关闭 Replay 后再次打开，恢复最后整体预览位置；新 Replay 首次自动打开除外。

---

## 14. 关键异常与边界

### 14.1 数据延迟或缺失

- 显示实际回测起止时间和数据最新时间。
- 缺失数据区间在 Timeline 和 K 线中明确标记。
- 不在缺失区间生成确定性 AI 解释。

### 14.2 Marker 过多

- Timeline 使用聚合 Marker。
- K 线缩放较远时合并或简化交易标记。
- 用户点击聚合后查看事件列表，再选择具体事件定位。

### 14.3 AI 洞察仍在生成

- 已完成的洞察可以先展示。
- 未完成区域展示明确的生成状态。
- 不用虚假的逐字动画延长等待。
- Replay 的 K 线、指标、Timeline 和交易记录不依赖全部洞察生成完成才能查看。

### 14.4 回放中切换 Replay

- 先停止当前 Replay 的自动播放。
- 打开目标 Replay。
- 目标 Replay 按“再次打开历史 Replay”的规则进入整体预览。
- 不把当前 Replay 的时间进度映射到另一条 Replay。

### 14.5 点击 Strategy

- 暂停回放并保存当前查看位置。
- 打开该 Replay 关联的历史 Strategy 详情。
- 返回 Replay 时恢复之前的模式、时间位置和 K 线视野；若此前正在自动播放，返回后保持暂停，由用户主动继续。

---

## 15. MVP 不做

- Replay 中手动模拟下单
- 隐藏最终回测指标制造结果悬念
- Timeline 缩放
- Timeline 视频或 K 线缩略图
- 双 Replay 同步播放
- 对每根 K 线生成 AI 旁白
- 自动播放每一个历史 Replay
- 允许修改 Replay 的交易、条件、指标或结论数据

## 16. 埋点

至少记录：

- 新 Replay 首次自动播放开始率
- 首次回放跳过率
- 首次回放完成率
- 从头回放点击率
- 继续回放点击率
- 回放平均观看时长
- Timeline 拖动次数
- 上一个 / 下一个事件使用率
- Marker 点击率
- AI 洞察点击率
- 洞察定位后询问 Agent 的比例
- 洞察定位后修改 Strategy 的比例
- Replay 到再次回测的转化率
- Replay 全屏率和面板宽度调整率

核心评价不是播放时长，而是：

> 用户是否通过 Replay 理解了一个策略行为，并产生了下一步研究行动。

## 17. 验收标准

### 整体预览

- 完整 K 线可见。
- 点击 Timeline 或 Marker 只定位，不隐藏未来数据。
- K 线缩放不改变 Timeline。
- 点击洞察后可以定位单一时刻或完整区间。

### 回放模式

- 进入回放后未来 K 线隐藏。
- Timeline 可以向前或向后自由拖动。
- 拖动后保持暂停。
- 普通区间快速通过，关键事件减速或停留。
- 用户可以随时退出回放并恢复完整 K 线。

### 指标

- 顶部指标始终是完整回测结果。
- 当前时刻数据与完整结果明显区分。
- 回放进度不会使完整结果指标产生跳变。

### AI 洞察

- AI Explain 只在关键决策和状态变化时出现。
- 每条关键洞察都可以追溯到时间、交易和策略规则。
- 点击洞察会暂停回放并进入完整行情定位。
- 用户可以从洞察进入 Agent 继续研究。

### 首次体验

- 新 Replay 生成后首次自动打开并从起点快速播放。
- 用户随时可以直接查看完整结果。
- 历史 Replay 再次打开时不自动重复播放。
- No Trades 不强制播放无事件的完整历史。

本方案确认后，视觉和交互稿至少需要覆盖：

5. 点击洞察定位

# Part C：Login

## C1. 登录触发方式

未登录用户可以浏览 New Conversation 并输入策略。以下行为进入独立 Login Page：

- 用户主动点击登录
- 未登录用户发送策略消息
- 未登录用户执行需要保存账户数据的操作

进入 Login Page 前保留用户已经输入的策略和原始操作。登录成功后自动返回并继续。

## C2. Google One Tap

未登录用户进入首页时，可以尝试展示 Google One Tap / FedCM 账号提示，作为降低登录阻力的可选入口。

- Desktop 通常由浏览器显示在页面右上区域。
- 提示的位置、账号列表和具体外观由 Google / 浏览器控制，产品不自定义。
- 用户可以关闭，不阻断输入策略。
- One Tap 可能因浏览器设置、用户关闭后的冷却、无可用 Google Session、H5 WebView 或其他环境原因不出现。
- 产品不能依赖 One Tap 完成登录，必须始终保留独立 Login Page。
- 已登录用户不展示 One Tap。

Google 官方参考：

- [Google One Tap](https://developers.google.com/identity/gsi/web/guides/display-google-one-tap)
- [Sign in with Google features](https://developers.google.com/identity/gsi/web/guides/offerings)

# Part D：当前交互范围

## D1. Runner 下载入口

Runner 只定义 Trade Lab 产品内的下载入口：

- 当前已完成回测的 Strategy 详情提供“下载 Runner”。
- 历史 Strategy 详情提供“下载 Runner”。
- Replay 详情提供“下载 Runner”，对应其关联历史 Strategy 代码。
- 当前 Strategy 存在未回测修改时，下载不可用并提示先完成回测。

点击后打开轻量确认层，展示：

- Strategy 名称与历史节点
- 从 Replay 发起时的 Replay 名称与回测时间
- 交易标的和周期
- 本次下载使用的 Strategy 代码来源
- 风险提示
- “下载 Runner”和“取消”

下载完成或失败在原位置反馈。客户端安装、配置、模拟、实盘和运行交互不属于当前方案。

## D2. 不再扩写的模块

除全局框架、Replay 和最小登录外，MVP 不再为以下内容单独扩写交互方案：

- Agent Conversation：沿用 Claude / ChatGPT 的标准消息、输入框和卡片交互；业务规则以 PRD 为准。
- Strategy 详情、历史切换与恢复：直接按 PRD 已确认流程出设计稿。
- Replay Compare：MVP 不提供独立比较页面或比较操作；用户可以直接让 Agent 基于历史 Replay 回答比较问题。
- Runner：产品只定义 Strategy / Replay 中的下载入口和下载前来源确认；客户端安装、模拟、实盘和运行交互由技术侧调研后另行确定。
- Subscription、Usage、积分和定价：等待技术成本测试和商业方案后再设计。
- 通用异常与反馈：使用成熟 Web / H5 产品惯例处理，不在当前阶段逐项扩写。
