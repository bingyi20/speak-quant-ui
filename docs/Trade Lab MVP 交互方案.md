---

## 1. 文档目的

本文档是 SpeakQuant MVP 唯一的详细交互方案，用于统一定义各模块的页面布局、操作路径、状态切换、反馈、异常、响应式行为与交互验收标准。

本文档描述产品应呈现的行为，不规定图表库、数据结构、播放器实现或其他技术方案。

术语遵循[产品术语](产品决策.md#产品术语)：中文统一为“回测”，英文为“Backtest”；回测工作区称为“Backtest Workspace”。历史过程的时间推进交互称为“播放 / Playback”。接口、字段和内部模块仍沿用 Replay 命名。

所有 MVP 模块的详细交互持续追加到本文档，不再为单一模块创建独立交互方案。总 PRD 负责定义业务需求与产品边界，本文档负责说明用户如何操作以及界面如何响应。

---

## 2. 文档结构与维护规则

本文档按用户体验模块组织，模块之间共享统一的 Conversation、右侧资产面板和导航状态。

当前交互范围：

1. 全局产品框架与导航
2. Landing / New Conversation
3. Login
4. Backtest Workspace
5. Runner 下载入口

Agent Conversation 沿用成熟对话产品交互；Strategy 详情、历史切换与恢复直接按总 PRD 出设计稿，不在本文档重复描述。

维护规则：

- 已确认交互直接写入对应章节。
- 尚未确认的内容标记为“待讨论”，不写成最终规则。
- 跨模块的相同状态只定义一次，其他章节通过引用避免重复或冲突。
- 每轮交互讨论结束后同步更新本文档、总 PRD 和必要的产品决策。

# Part A：全局产品框架与导航

## A1. 设计结论

SpeakQuant MVP 直接沿用 Claude / ChatGPT 已被用户熟悉的 Agent 产品交互框架：

- 左侧可收起导航栏
- 新研究入口
- 收藏 Conversation 与全部 Conversation
- 中央 New Conversation / Agent Conversation
- 底部固定对话输入框
- 当前 Conversation 的右侧资产入口

不为 Trade 场景重新设计交易终端式全局框架。SpeakQuant 的产品差异集中体现在 Strategy、Agent 协作式回测、动态研究过程、Backtest 和 Runner，而不是全局导航。

本方案借鉴成熟产品的交互心智，不复制其品牌标识、视觉资产或具体样式。

## A2. Desktop 全局布局

```text
┌───────────────┬──────────────────────────────────────────────────────┐
│ SpeakQuant    │                                               资产   │
│               │                                                      │
│ ＋ 新研究      │                                                      │
│               │                 中央主内容区域                        │
│ 收藏          │                                                      │
│ Conversation ⋯│         New Conversation / Conversation             │
│               │                                                      │
│ 全部          │                                                      │
│ Conversation ⋯│                                                      │
│ Conversation ⋯│                                                      │
│               │                                                      │
│ 账户 / 用量   │                                                      │
└───────────────┴──────────────────────────────────────────────────────┘
```

全局采用三层结构：

1. 左侧：Conversation 导航
2. 中央：新研究或当前 Agent Conversation
3. 右侧：当前 Conversation 的 Strategy / Backtest 资产面板

右侧资产面板默认关闭，不长期占据中央对话空间。

## A3. 默认进入 New Conversation

用户登录后每次重新进入产品，默认打开空白 New Conversation，不自动进入最近 Conversation，也不默认展示资产 Dashboard。

首页只承担一个核心任务：

> 输入一个交易想法并开始研究。

首页不展示：

- 实时行情
- 币价涨跌榜
- 市场热力图
- 当前持仓
- 历史收益 Dashboard
- 全局 Strategy 列表
- 全局 Backtest 列表
- Runner 运行状态

历史研究通过左侧 Conversation History 进入。

## A4. New Conversation 页面

```text
┌──────────────────────────────────────────────────────────┐
│                                                          │
│                       SpeakQuant                         │

│              3 分钟，验证你的交易想法                    │

### A4.1 输入框

- 使用大型多行输入框。
- 右下角使用仅含向上箭头的圆角方形发送按钮。
- 空输入时按钮不可用。
- 支持键盘快捷提交和换行。
- 输入内容在登录、刷新或返回后不能丢失。
- Placeholder 使用自然语言示例，不要求用户填写结构化表单。

### A4.2 Quick Examples

输入框下方展示最多 4 个真实策略示例：

- 趋势跟随
- 放量突破
- 均值回归
- 多周期做多 / 做空

Quick Examples 用于提供可编辑的策略输入，不用于介绍产品功能。

点击示例后：

- 将完整示例填入输入框。
- 不立即提交。
- 用户可以继续修改。
- 输入框获得焦点。

不使用“创建策略、运行回测、查看 Backtest、生成 Runner”等产品功能卡作为 Quick Examples。

### A4.3 Conversation 创建时机

- 点击“新研究”只打开空白 New Conversation。
- 用户第一次发送有效内容后才正式创建 Conversation。
- 没有发送内容的空白页面不进入 Conversation History。
- Conversation 标题在首次有效交互后由 AI 根据研究想法生成。

## A5. 左侧导航栏

### A5.1 顶部固定区

- SpeakQuant Logo / 名称
- “＋ 新研究”
- 收起 / 展开侧栏

用户在任何页面点击“新研究”后进入空白 New Conversation，不删除或修改当前 Conversation。

### A5.2 Conversation History

Conversation History 只包含两个列表：

1. **收藏**
2. **全部**

- “收藏”展示用户已经收藏的 Conversation，按最近更新时间倒序。
- “全部”展示全部 Conversation，按最近更新时间倒序。
- 已收藏的 Conversation 同时保留在“全部”列表中；收藏区是快捷入口，不是从全部列表移动出来的独立目录。
- 没有收藏内容时，收藏区可以折叠或展示简洁空状态。

每条记录以 Conversation 标题作为主要信息，右侧固定提供三点菜单。MVP 不在左侧直接展示：

- Strategy 状态
- Backtest 数量
- 回测收益或回撤
- Runner 状态
- 版本号
- “正在使用”等标签

点击一条历史记录后，恢复完整 Conversation、当前 Strategy 状态和对应右侧资产上下文。

点击 Conversation 右侧三点菜单后展示：

- 收藏状态切换：“收藏”或“取消收藏”
- 重命名
- 删除

菜单规则：

- 点击菜单外区域、按 Esc 或完成操作后关闭。
- 收藏状态切换后立即更新收藏列表，不影响全部列表的位置和排序。
- 重命名进入就地编辑或轻量弹窗；保存后两个列表中的标题同步更新。
- 删除属于不可恢复操作，必须展示二次确认弹窗。

删除确认必须说明：

- Conversation 删除后不可恢复。
- 该 Conversation 下的当前 Strategy、历史策略节点、Conversation History 和全部 Backtest 将一并删除。
- 已经下载到用户本地的 Runner 包不受影响。

确认按钮使用明确文案“永久删除”，不使用含糊的“确定”。取消是默认安全操作。

### A5.3 底部固定区

账户入口固定放在左侧导航栏底部，不放在产品右上角。底部可以包含：

- 用户头像、名称或邮箱
- 帮助
- 语言
- 设置

不向用户展示 Token。

### A5.4 收起状态

侧栏收起后只保留：

- Logo
- 新研究
- 展开按钮
- 用户头像

收起和展开不改变中央 Conversation 的滚动位置，也不关闭已经打开的右侧资产。

## A6. 中央 Conversation

进入历史 Conversation 后，中央区域使用标准 Agent 对话结构：

- 用户自然语言消息
- 用户消息发送后立即以正常气泡展示，不显示发送中或成功标记；只有失败时才显示轻量提示和重试入口。
- AI 文本回复
- Clarify 底部逐题问答卡片，展开时位于普通输入框上方，普通输入框始终可见
- Strategy 生成 / 更新摘要
- Backtest 执行状态卡
- 动态研究过程
- Backtest 卡片
- Runner 相关操作卡

普通文本保持舒适阅读宽度；Strategy 和 Backtest 等结构化卡片可以使用更宽内容区域。

Clarification 当前采用逐题交互（2026-09-09 调整）：一次展示一道题，用户选择后进入下一题，最后统一提交。卡片位于底部输入区域，展开时位于普通输入框上方，普通输入框始终可见；普通文字输入和独立草稿始终保留，已填答案保留并可继续作答。每题均提供 Skip；末题选择选项、回车确认或 Skip 时一次提交此前已填的有效答案（可部分填写或全部跳过，后端支持待同步），此前逐题选择不发送；提交中防止重复操作，失败保留答案。历史问题只读回看，协议继续使用 `clarification_card`。具体交互与状态以 [Agent 对话模块技术方案 §8.3](./Agent%20对话模块技术方案.md#83-底部逐题快捷问答) 为准。

底部输入框固定：

- 同会话的 Agent 回复全部结束前，用户可以继续输入和换行，但不能发送下一条消息；普通发送与 Clarification 提交遵循同一规则。回复结束后恢复发送，不自动提交已输入的草稿。
- 本期没有暂停/停止消息能力，回复期间发送按钮禁用。后续后端支持暂停后，再将这个按钮切换为可点击的暂停功能。
- 支持继续修改当前 Conversation 唯一对应的 Strategy。
- 用户正在查看右侧 Strategy 或 Backtest 时仍可继续对话。
- 从 Backtest 洞察发起追问时，将对应 Backtest 与时间位置带入对话上下文。

## A7. 顶部栏

顶部栏保持克制，只提供当前场景必要操作。

New Conversation：

- 侧栏展开 / 收起

历史 Conversation：

- 侧栏展开 / 收起
- Conversation 标题
- 当前 Conversation 的资产入口

MVP 不提供复杂的一级导航、行情频道或多个 Workspace Tab。

## A8. 右侧资产入口

当前 Conversation 形成 Strategy 后，顶部右侧显示资产入口。点击后打开该 Conversation 的统一资产列表：

1. 第一张固定为当前 Strategy。
2. 下方展示“回测记录 · N”及全部 Backtest。

右侧面板规则：

- 默认关闭。
- 资产列表使用较窄面板。
- 打开 Strategy 或 Backtest 详情后扩展到右侧约 50%。
- 中央 Conversation 与右侧详情之间的分隔线可拖动。
- 同时只打开一个资产详情。
- 关闭后中央 Conversation 恢复主要空间。
- New Conversation 尚未形成 Strategy 时不展示资产入口或使用不可执行的弱状态。

Backtest 新生成后可以自动打开右侧 Backtest Workspace。该行为不改变左侧 Conversation 的选择和中央 Conversation 的滚动位置。

## A9. 视觉方向

全局视觉保持安静、清晰、可信，避免通过交易终端元素制造专业感。

不采用：

- 首页实时行情和闪烁价格
- 大面积红绿涨跌色
- 订单簿式信息密度
- 赛博朋克霓虹
- 交易所式复杂导航

SpeakQuant 的研究感通过以下部分形成：

- Strategy 和 Backtest 的差异化资产结构
- 清晰的已验证 / 未验证状态
- Agent 回测与研究过程
- K 线、Timeline 和 AI 洞察
- 精确、易比较的价格、时间和指标数字

全局框架的熟悉度优先于装饰性创新；核心研究体验的辨识度优先于首页“酷感”。

## A10. H5 与响应式原则

Desktop：

- 左侧导航 + 中央 Conversation + 可选右侧资产。

H5 是 SpeakQuant MVP 的主要获客入口，不是只读兼容版本。H5 必须完整支持：

- Landing 与 Quick Examples
- 输入策略并在登录后恢复原始内容
- Login
- Clarify
- Agent 发起回测与必要的 Clarify
- Conversation 动态过程
- Strategy 查看
- Backtest 查看与核心交互
- 基于洞察继续询问 Agent
- 修改 Strategy 并发起下一次回测

### A10.1 H5 全局框架

- 页面默认只显示中央 New Conversation 或 Conversation。
- 左上角使用菜单按钮打开侧栏抽屉。
- 侧栏抽屉展示“新研究、收藏、全部、账户”。
- 账户入口固定在抽屉底部。
- 抽屉打开时不丢失当前输入、Conversation 滚动位置或 Backtest 状态。
- 选择 Conversation 后自动关闭抽屉并进入目标会话。
- Conversation 三点菜单使用适合触控的操作菜单或 Bottom Sheet。
- 所有关键点击区域满足触控尺寸，不能依赖 Hover 才能发现。

### A10.2 H5 New Conversation

- 标题、输入框和 Quick Examples 适应单列布局。
- 输入框保持页面核心视觉位置。
- Quick Examples 可以横向滑动或使用紧凑两列布局，不占满首屏。
- 移动键盘弹出时，发送按钮保持可见。
- 登录中断后必须恢复用户原始策略输入。

### A10.3 H5 Conversation

- 底部输入框固定，并适配设备安全区域与移动键盘。
- Strategy 卡和 Backtest 卡使用单列宽卡。
- 当前 Conversation 的资产入口放在顶部右侧。
- 点击资产入口后以全屏层打开资产列表，而不是在小屏并排挤压 Conversation。
- 关闭资产层后恢复 Conversation 原滚动位置。

### A10.4 H5 Backtest

- Backtest 在 H5 使用全屏 Workspace，不与 Conversation 左右并排。
- K 线仍是视觉主体。
- Timeline 保持固定完整区间，可触控拖动。
- AI 洞察使用底部抽屉或独立层展开。
- 用户可以返回 Conversation，返回 Backtest 时恢复时间位置和选中洞察。
- H5 必须支持历史定位、首次播放、暂停、拖动 Timeline、定位末端和点击洞察定位。

Desktop 和 H5 共享相同业务状态与资产，不形成两套产品逻辑。布局可以不同，但关键操作和研究结论必须一致。

## A11. 全局框架验收标准

- 用户每次进入产品默认可以立即输入新的交易想法。
- 未发送的空白 New Conversation 不进入历史。
- 左侧只承担 Conversation 导航，不演变为 Strategy 资产管理器。
- 用户可以从历史 Conversation 恢复完整研究上下文。
- 用户可以通过收藏快速访问 Conversation，全部列表始终按最近更新时间倒序。
- 每条 Conversation 的三点菜单可以切换收藏、重命名和永久删除。
- 永久删除必须二次确认并明确不可恢复。
- 用户查看 Strategy 或 Backtest 时仍能继续与 Agent 对话。
- 右侧资产只属于当前 Conversation。
- 首页不因交易场景增加实时行情或复杂 Dashboard。
- Quick Examples 可以一键填入并继续编辑，不会自动提交。
- 侧栏和资产面板的开关不丢失 Conversation 与 Backtest 状态。
- 账户入口只位于左侧导航底部或 H5 侧栏抽屉底部，不出现在产品右上角。
- H5 可以完整完成从输入策略到查看 Backtest、追问洞察和再次回测的核心闭环。

# Part B：Backtest Workspace

## 3. Backtest 的产品定义

Backtest 是一次回测完成后形成的只读实验资产，同时承载：

- 完整回测结果
- 历史 K 线和策略交易节点
- 策略决策过程
- 可定位的 AI 洞察
- 回测条件、交易记录与研究结论

Backtest 的核心定位是：

> **一份可播放、可定位、可解释、可追溯的策略实验报告。**

Strategy 说明“策略准备如何交易”；Backtest 证明“策略实际上如何交易，以及为什么”。

Backtest 不是：

- 用于隐藏未来行情并训练用户主观交易能力的练盘工具
- 允许用户手动模拟下单的交易模拟器
- 单纯逐根播放 K 线的视频
- 只有收益指标和买卖箭头的传统回测报告
- 可以被修改、覆盖或恢复的策略实体

---

## 4. 核心价值

Backtest 需要帮助用户完成四件事：

### 4.1 检查可信度

用户可以检查策略在某个时刻看到了什么条件、为什么交易、如何改变仓位，以及费用、止损、止盈或强平如何影响结果。

### 4.2 理解决策过程

Backtest 将一次交易还原为：

`市场状态 → 规则满足 → 策略决策 → 仓位变化 → 交易结果`

### 4.3 发现策略问题

用户可以快速定位最大亏损、最大回撤、连续亏损、异常交易、失效区间和成本侵蚀。

### 4.4 进入下一轮研究

用户从 Backtest 中发现问题后，可以回到 Agent 提出修改，形成新的 Strategy 状态并再次回测。

Backtest 的终点不是“播放结束”，而是产生新的研究行动。

## 5. 页面结构

### 5.1 半屏 / 全屏布局

所有尺寸均采用全宽图表、下方证据区。完整尺寸、各状态线框和逐项操作路径见[回测详情模块技术方案 §3](回测详情模块技术方案.md#3-页面设计与操作流程)。

┌──────────────────────────────────────────────────────────────────────┐
│ 回测名称 / 切换回测                  查看策略        更多  全屏  关闭 │
│ BTC/USDT · 执行 15m · 永续 · 双向 · 3× · 实际日期区间          条件 │

│ 查看周期 [15m] [1h] [4h] [1D]                        成交量    复位 │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                          全宽 K 线                                    │
│                成交标记 / 选中交易 / 证据区间                         │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ 选中或播放时：当前时间 · 仓位 · 累计收益 · 当前回撤                    │
│ 时间位置 / 播放控制                                                   │
│ 开始日期 ─────●──────▲────────●──────────────●────────── 结束日期   │
├──────────────────────────────────────────────────────────────────────┤
│ [洞察 N] [交易 N]                                             展开   │

```

执行周期保持冻结；查看周期的 K 线由后端扩展接口直接返回，前端不聚合行情。选项以服务端支持清单为准，切换不改变回测结果。当前扩展尚待接口契约与真实联调，接入要求见技术方案 §3.6、§6.5。

### 5.2 空间优先级

1. K 线是页面最大视觉主体，半屏与全屏均占内容可用宽度 100%。
2. 洞察与交易在图表下方按需展开；自动事件只更新摘要，不改变图表宽高。
3. 顶部只固定展示最关键的完整回测指标。
4. Timeline 高度固定，不展示视频缩略图或 K 线预览。
5. 详细指标、交易记录、策略规则和回测条件采用按需展开。

## 6. 一个历史截止位置

Backtest 只有一个当前位置。首开默认最后一根，全部过程可见；拖回过去时，图表与证据只显示到当前位置的收盘。暂停不恢复未来数据，播放只推进位置，不存在额外浏览/播放模式切换。

## 7. 查看历史过程

- 时间轴始终覆盖完整数据区间，点击或拖动到任意位置会暂停、设置截止点并定位图表。
- 桌面点击 K 线或成交 TAG 只查看图内信息，不改变截止位置；拖动图表只改变视野并暂停，不能浏览截止位置以后的 K 线。手机暂保留现有行为。
- 拉到时间轴末端即可查看全程和全局洞察。桌面顶部指标跟随时间轴，历史位置标记“截至此时”，末端标记“最终结果”。
- 点交易或成交标记定位到其实际时刻；global 洞察在末端阅读，选择它只移动图表至证据区间。

## 8. 播放与暂停

- 控制栏保持到开始、播放/暂停、到结束、速度和当前日期时间。末端显示从头播放，其余位置从当前处继续。
- 播放使用冻结执行周期，按相对倍速逐根揭示（桌面默认 1x，可选 0.5x/1x/2x/5x/10x；手机暂保留原速度显示）。无事件区间不隐式压缩，桌面成交仅额外短暂停顿（最多 150ms，随倍速缩短），手机成交保留 1.2 秒，runtime 洞察保留 2.4 秒。
- 拖轴、图表平移/缩放、查看证据、切后台均暂停，松开或返回前台不会自动继续。
- 当前根收盘后的持仓/权益由后端 state 展示，不用前端重算；缺口暂停并允许明确跳到下一根。
- 自然结束停在末端并显示全段内容，不改变布局。
- 暂停时可查看后端支持的其他周期，仅显示截止时间前已收盘的完整 K 线；切周期不改变策略执行含义。

## 9. Timeline 与成交标记

- 固定日期范围的单条时间轨道，高 78px，含日期刻度、已发生区域与贯穿轨道的垂直指针；图表缩放不改变轨道。
- 买入、卖出、runtime 洞察使用不同颜色小点和图例，均在同一条轨道；未来事件不显示。
- 密集标记形成点组而非裸数字，点击展示含动作/洞察标题、交易序号、日期的事件列表，再选中定位。
- K 线使用清晰的实心尖角 B/S TAG，连接到实际成交价；B/S 是买/卖，明细再区分开多、平多、开空、平空。近邻避让，同根同侧多笔用 B×n/S×n。
- 左上行情读数包含日期时间/星期、开高低收、涨跌额、涨跌幅、成交量。关闭成交量柱图不隐藏成交量数值；涨跌以前一相邻 K 线收盘为基准，缺失则“—”。
- 时间轨道支持点击、拖动和键盘逐根/跨段/首末定位。桌面统计最大盈利/亏损/回撤收进固定“结果定位”菜单，只改变图表视野，未揭示区间禁用；手机保留末端入口。不增加事件计数。

## 10. 顶部回测指标

### 10.1 固定展示完整结果

顶部核心指标始终展示完整回测结果，不跟随 Timeline 或播放进度变化。

建议固定展示：

- 净收益率
- 最大回撤率
- 交易次数
- 胜率
- Profit Factor 或盈亏比

桌面顶部随截止点显示“截至此时”或“最终结果”，取消下方重复状态行，状态详情由标题旁“查看详情”进入；手机暂保留原展示。

### 10.2 当前时刻动态状态

当前进度信息单独展示在 K 线与 Timeline 之间，并随定位点或播放指针变化：

- 当前日期和时间
- 当前持仓方向（持有多仓/持有空仓/空仓）
- 截至该根 K 线收盘的收益
- 截至当前的回撤
- 当前持仓浮动盈亏
- 当前杠杆或强平距离（适用时）

用户可以展开查看更多状态，但动态信息不得取代顶部完整结果。

## 11. AI 洞察

### 11.1 洞察类型

AI 洞察至少分为：

- 整体结论
- 关键盈利与亏损事件
- 风险和失效区间
- 异常交易行为
- 改进机会
- 下一步研究建议

每条洞察包含：

- 简短结论
- 对应时间点或时间区间
- 支撑数据或交易证据
- 洞察类型
- 已验证结论或待验证假设标记

### 11.2 截至当前位置的证据

图表下始终保留“洞察 / 交易记录”两个 Tab，含义不随播放改变。runtime 洞察在发生时揭示，global 仅末端显示；未平仓 Trade 不显示未来退出信息、最终盈亏或尚未发生的 Fill。回退后所有未来记录及计数撤回。

### 11.3 播放中的更新

只更新已发生内容及必要的短摘要，不自动展开、不抢滚动、不生成普通 K 线旁白。播放不等待新的 AI 解释生成。

### 11.4 点击洞察

暂停并在图表下展开正文与证据。runtime 定位对应执行周期 K 线并更新截止位置；global 保留末端截止，只改变证据视野。无法定位时保留可读内容并显示局部错误，不恢复未来行情或切换模式。证据区间不超过截止位置。

### 11.5 与 Agent 的衔接

洞察详情提供：

- 询问 Agent
- 基于该发现提出修改
- 查看相关交易

从 Backtest 发起的追问必须携带当前 Backtest、时间点或区间、交易事件和关联历史 Strategy 上下文。对话回复仍出现在中央 Conversation。

## 12. 首次打开与再次打开

### 12.1 新 Backtest 首次自动打开

本轮连接确实观察到新回测完成，且用户没有正在输入、阅读其他面板或处理澄清问题时，消费一次自动打开意图：

1. Conversation 输出回测卡片，工作区自动展开。
2. 主周期索引、成交目录与洞察请求就绪后，从第一根开始播放；后台页面或减少动态效果设置不自动播放。
3. 用户随时可暂停、拖轴，或用“到结束”直接定位末端；这些操作取消自动继续。
4. 成交和洞察处短暂停留，自然结束后停在末端并显示全程内容。

桌面首次播放时顶部展示截至当前时间的指标，末端恢复完整回测结果。历史详情不得混入未来交易的最终统计。

### 12.2 再次打开历史 Backtest

用户以后通过 Conversation 卡片、资产列表或 Backtest 切换器重新打开时：

- 默认定位末根并暂停。
- 不自动重复播放。
- 已有查看快照时恢复原截止位置、周期和视野，保持暂停。
- 末端提供从头播放，其他位置提供播放。

### 12.3 No Trades

No Trades Backtest 首次打开时：

- 默认定位末根并暂停，不自动播放完整历史。
- AI 解释哪些入场条件从未满足。
- Timeline 标记最接近触发的阶段（能够确定时）。
- 用户仍可主动进入播放检查相关阶段。

### 12.4 直接查看完整过程

拉到时间轴末端或点击“到结束”后：

- 立即暂停时钟。
- 恢复完整 K 线。
- 定位末根并暂停。
- AI 展示整体结论。
- 本次 Backtest 后续重新打开不再自动播放。

## 13. 响应式与右侧面板

### 13.1 默认半屏

Backtest 默认在 Conversation 右侧约 50% 宽度打开。

- K 线使用面板内容全宽，不放常驻右侧洞察栏。
- 图表下方依次是播放控制、固定时间轴、洞察/交易证据区。
- 证据区默认一条简短结论；用户点展开才显示正文与证据。
- 关键事件只更新固定高度摘要，不自动打开抽屉或抢夺滚动位置。
- 用户可以拖动 Conversation 与 Backtest 之间的分隔线增加 Backtest 宽度。

### 13.2 宽屏 / 全屏

- 图表仍为全宽，利用新增宽度显示更多行情细节，利用高度增大绘图区。
- 洞察与交易仍在下方，不改为 70% / 30% 横向分栏。
- 长报告、条件和完整指标使用用户主动打开的阅读层；关闭后恢复原视图。
- 手机减少首屏次级指标、折叠周期控件，保持图表可操作高度；长证据通过底部阅读层查看。

### 13.3 全屏与退出

- 全屏不改变当前截止位置、播放进度、K 线视野和选中洞察。
- 退出全屏后恢复此前半屏宽度。
- 关闭 Backtest 后再次打开，恢复最后截止位置并暂停；新 Backtest 首次自动打开除外。

## 14. 关键异常与边界

### 14.1 数据延迟或缺失

- 显示实际回测起止时间和数据最新时间。
- 缺失数据区间在 Timeline 和 K 线中明确标记。
- 不在缺失区间生成确定性 AI 解释。

### 14.2 Marker 过多

- 桌面 Timeline 买入/卖出/洞察各自水平对齐，每个事件按实际时间独立显示与点击，不合并；手机暂保留聚合 Marker。
- K 线缩放较远时合并或简化交易标记。
- 桌面 Timeline 点击单个事件直接定位；K 线同根聚合 TAG 与手机原聚合入口保留事件选择。

### 14.3 AI 洞察仍在生成

- 已完成的洞察可以先展示。
- 未完成区域展示明确的生成状态。
- 不用虚假的逐字动画延长等待。
- Backtest 的 K 线、指标、Timeline 和交易记录不依赖全部洞察生成完成才能查看。

### 14.4 播放中切换 Backtest

- 先停止当前 Backtest 的自动播放。
- 打开目标 Backtest。
- 目标 Backtest 按“再次打开历史 Backtest”的规则定位末根并暂停。
- 不把当前 Backtest 的时间进度映射到另一条 Backtest。

### 14.5 点击 Strategy

- 暂停播放并保存当前查看位置。
- 打开该 Backtest 关联的历史 Strategy 详情。
- 返回 Backtest 时恢复之前的时间位置和 K 线视野；若此前正在自动播放，返回后保持暂停，由用户主动继续。

## 15. MVP 不做

- Backtest 中手动模拟下单
- 隐藏最终回测指标制造结果悬念
- Timeline 缩放
- Timeline 视频或 K 线缩略图
- 双 Backtest 同步播放
- 对每根 K 线生成 AI 旁白
- 自动播放每一个历史 Backtest
- 允许修改 Backtest 的交易、条件、指标或结论数据

- 首次播放完成率

## 17. 验收标准

### 历史位置与播放

- 默认末根，全部行情与证据可访问。
- 点击/拖动时间轴设置唯一截止点，松开暂停；未来 K 线、成交、洞察和统计数量撤回。
- 桌面图表平移、缩放、单击可见 K 线或成交 TAG 均不改变截止点，也不能看到未来；时间轴单向控制图表内容。
- 播放从当前位置继续，逐根揭示；回到末端自然恢复完整内容，无模式切换按钮。
- 多周期只展示截止时已收盘 K 线；未平仓交易不提前出现最终盈亏。
- 单条轨道的彩色点可定位，K 线 B/S TAG 清晰且能选中，行情数据始终包含成交量。

### 指标

- 顶部指标始终是完整回测结果。
- 当前时刻数据与完整结果明显区分。
- 播放进度不会使完整结果指标产生跳变。

### AI 洞察

- AI Explain 只在关键决策和状态变化时出现。
- 每条关键洞察都可以追溯到时间、交易和策略规则。
- 点击洞察会暂停播放并进入完整行情定位。
- 用户可以从洞察进入 Agent 继续研究。

### 首次体验

- 新 Backtest 生成后首次自动打开并从起点快速播放。
- 用户随时可以直接查看完整结果。
- 历史 Backtest 再次打开时不自动重复播放。
- No Trades 不强制播放无事件的完整历史。

# Part C：Login

## C1. 登录触发方式

未登录用户可以浏览 New Conversation 并输入策略。以下行为进入独立 Login Page：

- 用户主动点击登录
- 未登录用户发送策略消息
- 未登录用户执行需要保存账户数据的操作

进入 Login Page 前保留用户已经输入的策略和原始操作。登录成功后自动返回并继续。

## C2. Google One Tap

未登录用户进入首页时，可以尝试展示 Google One Tap / FedCM 账号提示，作为降低登录阻力的可选入口。

- Desktop 通常由浏览器显示在页面右上区域。
- 提示的位置、账号列表和具体外观由 Google / 浏览器控制，产品不自定义。
- 用户可以关闭，不阻断输入策略。
- One Tap 可能因浏览器设置、用户关闭后的冷却、无可用 Google Session、H5 WebView 或其他环境原因不出现。
- 产品不能依赖 One Tap 完成登录，必须始终保留独立 Login Page。
- 已登录用户不展示 One Tap。

Google 官方参考：

- [Google One Tap](https://developers.google.com/identity/gsi/web/guides/display-google-one-tap)
- [Sign in with Google features](https://developers.google.com/identity/gsi/web/guides/offerings)

- H5 Login Page 使用相同信息层级和单列布局。
- Google One Tap 在部分移动浏览器或 WebView 中可能不展示，不能影响手动 Google 按钮和邮箱验证码登录。
- OAuth 或浏览器跳转返回后，恢复登录前策略输入与 Conversation 状态。

# Part D：当前交互范围

## D1. Runner 下载入口

Runner 只定义 SpeakQuant 产品内的下载入口：

- 当前已完成回测的 Strategy 详情提供“下载 Runner”。
- 历史 Strategy 详情提供“下载 Runner”。
- Backtest 详情提供“下载 Runner”，对应其关联历史 Strategy 代码。
- 当前 Strategy 存在未回测修改时，下载不可用并提示先完成回测。

点击后打开轻量确认层，展示：

- Strategy 名称与历史节点
- 从 Backtest 发起时的 Backtest 名称与回测时间
- 交易标的和周期
- 本次下载使用的 Strategy 代码来源
- 风险提示
- “下载 Runner”和“取消”

下载完成或失败在原位置反馈。客户端安装、配置、模拟、实盘和运行交互不属于当前方案。

## D2. 不再扩写的模块

除全局框架、Backtest 和最小登录外，MVP 不再为以下内容单独扩写交互方案：

- Agent Conversation：沿用 Claude / ChatGPT 的标准消息、输入框和卡片交互；业务规则以 PRD 为准。
- Strategy 详情、历史切换与恢复：直接按 PRD 已确认流程出设计稿。
- Backtest Compare：MVP 不提供独立比较页面或比较操作；用户可以直接让 Agent 基于历史 Backtest 回答比较问题。
- Runner：产品只定义 Strategy / Backtest 中的下载入口和下载前来源确认；客户端安装、模拟、实盘和运行交互由技术侧调研后另行确定。
- Subscription、Usage、积分和定价：等待技术成本测试和商业方案后再设计。
- 通用异常与反馈：使用成熟 Web / H5 产品惯例处理，不在当前阶段逐项扩写。
