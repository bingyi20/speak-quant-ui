# 订阅与积分模块技术方案

> 更新日期：2026-09-22。当前阶段：前端 UI 预览，尚未接入订阅、订单、支付或积分接口。

## 1. 范围与边界

已实现 Free / Pro / Max 套餐展示、积分单价、按当前会员档位计算的积分加购、支付待上线提示，以及工作台全屏弹窗。可以从侧栏账户行“升级”、账户概览“升级套餐”、订阅设置“升级套餐”进入。

套餐、价格和当前会员均为前端静态预览；`Free` 不是接口返回的真实订阅。账户积分余额继续显示未接入状态，不把每月赠送额度当作余额。购买动作仅显示页面中上方居中的“支付功能待上线”短提示（2.2 秒后自动淡出，无图标、关闭按钮或倒计时条），重复点击合并为同一条提示；不创建订单、不调用支付接口、不修改会员或余额、不模拟支付成功。使用记录仍为占位。

`/pricing` 与 `/zh-CN/pricing` 保留 SSR，直接复用工作台弹窗内的完整 `PricingContent`，包含套餐、积分加购、金额计算及统一支付提示；无单独公共版分支、支付路由、API 或 BFF。两处统一跟随登录状态：已登录时将静态 Free 标记为当前套餐，访客只显示禁用的“免费套餐”，不提供“开始研究”入口；访客加购使用明确标注的 Free 示例费率。选择付费套餐或有效加购统一显示支付待上线提示。积分、计费说明及协议链接见[公开站点技术方案](公开站点技术方案.md)。

## 2. 临时价格与计算规则

单一数据源为 `app/features/billing/catalog.ts`，货币统一为美元（USD），金额以整数美分保存。暂定按月订阅，不提供尚未定义规则的年付、优惠券或团队套餐。

| 套餐 | 月费 | 每月积分 | 套餐内每 100 积分 | 加购每 100 积分 |
| --- | ---: | ---: | ---: | ---: |
| Free | $0 | 300 | 免费额度 | $1.50 |
| Pro | $30 | 3,000 | $1.00 | $1.20 |
| Max（推荐） | $100 | 13,000 | $0.77 | $0.90 |

- 付费套餐档位越高，套餐内积分单价越低；加购单价高于同档套餐单价。Free 为免费额度，不参与付费套餐单价比较。
- 加购快捷金额为 $5 / $10 / $20 / $50；支持 $5–$10,000 的整数自定义金额。
- 输入为空、负数、小数、指数形式、非数字或超出边界时，显示字段错误并禁用继续按钮。
- `quoteTopUp` 使用整数美分计算，积分向下取整：`floor(金额美分 × 100 / 每100积分价格美分)`。同样加购 $5，Free / Pro / Max 分别为 333 / 416 / 555 积分。
- 已登录时两处加购均读取静态 Free 档位，未登录时显式展示 Free 示例费率；两者均不能通过点选付费套餐改变加购价格，未来由真实会员信息决定。
- 公开价格页问答收敛为套餐差异、积分消耗、额度用完、续费取消和退款申请五项。移除逐项模拟消耗数据，改用模型、工具、任务复杂度及处理内容量解释消耗；保留查看已有内容不额外消耗的说明。共享预览提示明确 USD 币种；取消与退款在公开价格页分别简述，不在页脚单设入口。
- 已确认的产品规则：积分不足时，可一次性加购、升级至更高月度套餐，或等待当前周期结束并续费后刷新。升级时保留当前剩余积分，与新套餐额度累加；当前已是最高档 Max 时，到期前不能更换套餐，只能加购或等待续费。公开问答不再附加 Free 免费额度刷新说明。以上已同步中英文问答，尚未接入真实计费与余额。
- 已确认退款原则：订阅与积分加购属于虚拟产品，原则上不支持退款；重复扣款、支付异常、误付或未按约定交付付费服务等情况由客服核查，按适用规则补救或处理退款；适用法律规定的消费者权利及支付渠道强制规则不受限制。退款问答只说明退款，不重复续费或取消内容，不提供自助退款入口；真实售后处理尚未接入。
- 正式消耗、积分有效期、普通续费时的剩余额度结转、升级计价及计费周期如何处理仍待确认；升级时保留剩余积分已确定，不与普通续费结转混为一谈。页面预览不代表这些业务能力已实现。

## 3. 模块与复用契约

| 文件 | 职责 |
| --- | --- |
| `catalog.ts` | 套餐类型、临时目录、默认会员、金额边界与纯计算函数 |
| `components/PricingContent.vue` | 完整共享展示与支付预览入口，接收 `plans`、`currentPlanId`、`initialTab`、`headingTag`；通过 `checkout` 输出选择并统一管理待上线提示 |
| `components/PlanCard.vue` | 单套餐展示与选择，不读取全局弹层或认证状态 |
| `components/CreditTopUp.vue` | 接收套餐与可选 `preview`，区分会员费率与示例费率，管理金额输入、校验与计算，不读取账户 store |
| `components/SubscriptionModal.vue` | 只提供全屏 UModal、滚动与关闭容器，内部直接嵌入共享内容 |
| `index.ts` | 页面和应用壳使用的公开入口 |
| `app/assets/css/billing.css` | 模块布局与交互样式，只引用共享语义变量 |

`CheckoutSelection` 输出 `kind`、`planId`、`planName`、`amountCents`、`credits`。这是前端展示事件，不是订单 DTO，也不是服务端可信报价。

页面或弹窗都使用同一组件树及 `billing.css`，不再提供 `publicPage` 模式。默认使用工作台预览目录；`PricingContent` 在挂载后读取现有 `useAuthStore` 的认证状态，已登录时采用静态 Free 预览，身份恢复中或未登录时不标记当前套餐，加购以“加购单价示例”显示 Free 费率。`currentPlanId` 不传时使用该共享规则，显式传入套餐 ID 或 null 可覆盖；公开页不再单独覆盖当前套餐。挂载前保持无当前套餐的确定性首屏，避免认证恢复早于 hydration 造成标记不一致。Free 操作始终禁用，只展示“当前套餐”或“免费套餐”，不再提供研究跳转。传入非空但不在目录的会员 ID 时仍不显示加购表单，不擅自降级为 Free。公开页使用 `headingTag="h1"`，弹窗默认 `h2`，标题文案与样式共享。`checkout` 事件仍输出选择，但当前两处的待上线处理由 `PricingContent` 内部统一负责，卸载时清理提示定时器，支付提示不依赖全局弹层、浏览器存储或业务 API；认证只复用现有 store，不新增请求。真实支付上线时在共享购买入口接入会员校验及支付流程。结账前需展示最终价格／税费、币种、交付时间、续费授权与取消路径、退款和积分使用条件；销售方、支付渠道角色及条款依实际交易展示。Creem 的名义商户与买家条款须在付款前明确披露，不能因通用服务条款不点名渠道而省略。积分有效期、续费结转及升级计价尚待确定，不能用竞品规则填充。具体审核依据与发布缺口统一见[公开站点技术方案](公开站点技术方案.md#支付提审核对2026-09-22)。

## 4. 状态与关闭行为

- `useOverlaysStore().openPricing('plans' | 'credits')` 是全局入口，默认 `plans`。`pricingTab` 只保存展示意图，不存会员、余额或订单。
- 侧栏“升级”默认进入 `plans` 月度套餐页签，与账户设置按钮独立；关闭后恢复升级入口焦点。
- 从账户设置进入时，保留底层设置弹窗及页签；关闭订阅弹窗后恢复入口焦点。购买不新增确认弹窗，也不转移焦点。
- 移动端先关闭侧栏抽屉，等待 `after:leave` 后打开订阅弹窗；关闭后焦点回到展开侧栏按钮。桌面悬停侧栏也先退出预览再打开。
- 全屏弹窗右上角 X 和 Esc 可关闭；正文独立滚动，关闭按钮保持可用。Nuxt UI / Reka 负责焦点约束与背景滚动锁。
- 加购错误说明始终预留布局空间，正常状态隐藏且不进入无障碍树；积分数字行高度固定，数字／空值切换不改变结果区域高度，移动端单价固定另起一行。
- 同次打开切换会员／加购页签保留输入；关闭后再次打开重置为入口指定页签和最低金额。购买提示保留本次输入。
- 共享组件保留 SSR 内容，挂载前禁用页签、购买及加购表单，防止首次点击在事件绑定前丢失；挂载后启用。Nuxt UI 首屏选中态由 `::before` 绘制，挂载后换成 indicator；两者统一使用 surface 背景、圆角与阴影。挂载前页签虽然禁用，但不降低透明度，避免金色和明暗闪烁。
- 路由切换或用户身份变化关闭全局弹层，不将报价或输入持久化，也不影响研究草稿。
- 后续真实接入时，购买直接跳转第三方支付页面或展示支付二维码，不增加二次确认；订单必须由服务端核验当前会员、价格、额度与有效期；组件计算仅供展示。请求及幂等复用现有 HTTP 底座，不能把本地点击视为订阅生效。

视觉与响应式规范见[浅色版设计决策 §5.8](Trade%20Lab%20浅色版设计决策.md#58-订阅套餐与积分加购)。
