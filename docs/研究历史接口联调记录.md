# 研究历史接口联调记录

日期：2026-09-08。范围：工作台左侧记录、当前对话标题与账户切换清理。

## 接入结果

| 交互 | 真实接口 | 前端处理 |
| --- | --- | --- |
| 收藏分组 | `GET /conversations?scope=favorite&page=1&size=20` | 独立分页、加载更多 |
| 历史分组 | `GET /conversations?scope=non_favorite&page=1&size=20` | 由服务端筛选非收藏，独立分页、加载更多 |
| 收藏、取消收藏 | `PATCH /conversations/{id}` | 仅提交 `is_favorite`，使用返回的服务端状态 |
| 原位重命名 | `PATCH /conversations/{id}` | 提交去除首尾空格的 `title`；失败保留草稿 |
| 永久删除 | `DELETE /conversations/{id}` | 确认后发送 `X-Confirm-Delete: permanent` 与幂等键；重试复用同一键 |
| 直接打开较早的对话 | `GET /conversations/{id}` | 记录未在已加载列表时补取标题 |

写入成功后重新读取已加载的分页范围，避免 `updated_at` 改变导致 offset 分页跳项。失败显示提示与重试入口；退出登录或切换用户同步清空缓存并取消请求。API 关闭时显示离线提示，不使用应用内 Mock。

## 已核对的契约

核对依据为 `trade-api/app/api/conversation.py`、`app/controller/conversation.py` 和 `app/schemas/conversation.py`，未修改后端代码。

1. PATCH 响应 `data` 直接为 `ConversationSummary`，没有 `conversation` 包裹；GET 详情则有该包裹。接口文档 5.6 已补齐完整响应示例及读取层级。
2. 标题长度限制为 1–200 个字符，接口文档 5.6 已补齐。前端去除首尾空格，空输入取消修改，超长输入提示错误。
3. `last_message_at` 在实际模型中允许为空，前端类型已兼容 `null`。

## 当前 API 的限制

后端已增加 `scope=non_favorite`，此前“仅非收藏”筛选缺失的问题已解决。前端已使用该筛选项，移除本地排除收藏及补充分页逻辑；首次加载只请求两个分组各自的第一页。`scope=all` 仍保留在通用 API 类型中，侧栏不再使用。收藏与取消收藏会将记录移入对应分组，并重新校验两边已加载的分页范围。

分页按 `updated_at DESC` 排序，收藏与重命名也会调整位置。这与当前“最近更新”的历史一致；若后续要按最近消息排序，需要增加排序参数或改变契约。
